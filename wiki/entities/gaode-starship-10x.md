# 星舰 10X（高德研发交付 Agent）

## Overview（概览）

高德搜索技术团队建设的面向复杂研发任务协同推进的 **AI 原生研发交付 Agent**，是《信息业务 AI Native Builder》系列交付篇的核心对象。其核心是把成熟 Coding Agent 的执行能力接入团队研发过程，解决"Agent 能写代码、工程师仍要不断补背景/对齐目标/检查覆盖"的问题——通过知识库与长期记忆（Memory）分工组织上下文，以渐进式披露、知识订正双路径与 Memory 三层提炼，让 Agent 有据可查、有方法可参考，人的判断落到后续行动。高德技术一手自述，单信源，置信度中。

## Identity（身份）

- **归属**：高德（Amap）搜索技术团队。
- **性质**：面向复杂研发任务协同推进与跨仓交付的 AI 原生研发交付 Agent（星舰助手 + 执行 Agent + 知识库/Memory 体系）。
- **系列定位**：《信息业务 AI Native Builder》系列交付篇；同系列含总纲篇、数字员工篇（[[gaode-ad-linglingqi|广告凌凌漆]]、[[gaode-search-linglingqi|搜索凌凌漆]]）、现场篇（[[gaode-qingzhou-agent|轻舟 Agent]]）。另有星舰 Cloud Agent（云端任务执行管理，本篇未详述）。
- **核心目标**：把可重复的查证、交接与检查交给系统，把需要业务判断的取舍清楚地交到人面前。

## Important Facts（重要事实）

- **定位与结构**：星舰助手通过主会话承接目标，可展开执行或组织成任务；用户可补条件纠偏，问题与产物返回同一主会话。平台用任务/工作流组织阶段、产物与必要决策，执行 Agent 在仓库与运行环境中完成具体工作；代码评审、测试、发布结果仍来自团队已有研发系统。
- **知识与经验分工**：知识库说明"系统实际怎样实现"（仓库知识库：模块职责/调用关系/代码入口；跨域 KBase：术语/业务规则/跨系统架构/操作流程），Memory 提醒"遇到这类问题先查什么"。执行 Agent 拿到目标约束后仍需调工具核对当前事实。
- **渐进式披露四层**：仓库知识分项目入口→架构总览→模块摘要→源码四层，Agent 按问题决定读到哪层，需确认执行顺序/条件分支/副作用时再进源码与配置；每份模块摘要独立可读并提供继续查证入口。KBase 也沿用渐进式披露（空间入口一句话说明覆盖范围→按主题组织"链接+短摘要"→问题到页面导航）。
- **知识质量双路径**：脚本负责可机械核对的信号（入口引用可达、代码版本可定位、关联源文件变化），Agent 沿源文件指针读代码做语义审查（职责/条件分支/默认行为/上下游约定），工程师裁决哪些发现进入正式知识。区分"当前实现"（代码配置）与"期望规则"（业务负责人确认）。
- **知识订正案例**：知识库版本文件原写普通版本字符串无法定位代码提交，修订后指向可解析的 Git 提交，文档有了可核对的代码基线；另一例修正字段归属（把 customoperator 误写成 queryparams 子字段，实际属于 QRLine 结果行结构），并补齐被遗漏的消费者与源文件指针。
- **Memory 三层提炼**：会话层保存可追溯的经验候选→个人层从≥2 个独立任务语境提炼稳定做法→共享层选择可迁移实践、脱敏后供团队。个人记忆按用户隔离，共享经验系统自动提炼发布，保留来源、适用条件与验证状态；同一来源更新覆盖原候选，不把重试算成独立验证。
- **Memory 跨任务复用案例**：来自实际开发的"构建侧与运行侧需要同步登记"经验，经共享提炼后进入另一位工程师的分析任务，被转化为具体预检建议——一次任务中形成的检查方法成为团队后续任务的起点。
- **跨仓交付案例**：统一两仓默认缓存键前缀，请求/解析侧改回退值、聚合侧同步数据源默认值与测试常量，任一侧遗漏两端找不到同一份数据；星舰把约束写进整体方案与逐仓产物，两份 MR 均已合入。工程师负责方案与代码评审、合入和上线发布；本文核实到 MR 合入，正式发布及真实链路效果未纳入本例结论。
- **支撑数据**：2026 年 4-9 月，已核验记录覆盖 1,030 项开发任务，其中至少 676 项形成或更新了 MR（占比≥65.6%），共对应 740 条去重代码评审。7 月单月峰值 94.2%（172 项任务中 162 项有 MR 产出，形成或更新 175 条代码评审）。统计按独立开发任务计数，子流程与同一任务内重试不另算；MR 按唯一评审 ID 去重，多次更新只计一条。未核验到 MR 产出的任务不直接判为失败。

## Products / Projects（产品／项目）

- 星舰 10X（研发交付 Agent，交付篇核心）
- 星舰助手（主会话承接目标的交互入口）
- 仓库知识库（模块职责/调用关系/代码入口，渐进式披露四层）
- KBase（跨域业务知识库，术语/业务规则/跨系统架构/操作流程）
- Memory 三层体系（会话层/个人层/共享层经验提炼）

## Relationships（关系）

- **与轻舟**：同属高德 AI Native Builder 系列，[[gaode-qingzhou-agent|轻舟]]聚焦产品前端场景与真机验证，[[gaode-starship-10x|星舰 10X]]聚焦研发目标组织与跨仓交付，二者共用 Agent Teams 与云真机底座。
- **与凌凌漆系列**：[[gaode-ad-linglingqi|广告凌凌漆]]与[[gaode-search-linglingqi|搜索凌凌漆]]属数字员工篇（问题排查与经验迭代），星舰属交付篇（研发交付与知识工程），三套 Agent 共用业务知识、工具接入与评测支撑。
- **与 Coding Agent 知识库**：星舰的仓库知识库+KBase 双库、渐进式披露四层、知识订正双路径，是 [[coding-agent-knowledge-base|Coding Agent 知识库]]"域—场景—知识"建模方法与渐进披露协议在高德的工程落地，二者同向（按需供给、给可核验路径、随变更演进）。
- **与 Agent 记忆系统**：Memory 三层提炼（会话层→个人层→共享层）、保留来源/适用条件/验证状态、个人记忆按用户隔离，是 [[agent-memory-system|Agent 记忆系统]]"记忆积累≠能力积累、反馈先判适用范围"原则的工程实例。
- **与验收 Agent**：星舰的交付阶段分别检查评审、合入与发布结果，给用户与约定目标对应的结论；跨仓案例中"核实到 MR 合入，正式发布与真实链路效果未纳入结论"与 [[acceptance-agent|验收 Agent]]"研发验收通过≠交付完成≠效果确认"同向。
- **与 AI 原生 SDLC / 交付四环节**：星舰把知识组织、订正与经验复用放进同一条需求交付过程，对应 [[ai-native-sdlc|AI 原生 SDLC]] 的制品提交链驱动闭环与 [[ai-coding-delivery-four-stages|AI Coding 交付四环节]] 的上下文/评审/评估环节。

## Current Understanding（当前理解）

星舰 10X 的核心变化不是让 Agent 写更多代码，而是把"一次 Demo 的成就感"延伸到真实业务——把目标、背景、约定和结果持续接在一起，让可重复的查证/交接/检查交给系统、需要业务判断的取舍交到人面前。**解读**：其价值在于"让 Agent 有据可查、有方法可参考，也让人的判断落到后续行动中"，知识库提供当前系统的事实入口、Memory 提供检查线索，二者经工程师裁决后才进入正式知识。支撑数据（1,030 任务/676 MR/65.6%）为作者自报口径，MR 产出占比不等于交付质量或业务效果，须结合合入、上线与业务验收分别确认。
