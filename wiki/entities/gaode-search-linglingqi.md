# 搜索凌凌漆（高德搜索问题归因 Agent）

## Overview（概览）

高德搜索技术团队建设的面向搜索业务问题排查的 **AI 原生数字员工 Agent**（代号 007），是《信息业务 AI Native Builder》系列数字员工篇的核心对象之一。基于开源 Hermes Agent 基座建设，解决海量 VOC（Voice of Customer，用户反馈）工单排查提效与经验沉淀，接 Case 后自查数据、走链路、给结论。截至 2026 年 10 月累计处理上万条用户提问，覆盖主搜、车机、详情页、销售、广告等多条业务线。高德技术一手自述，单信源，置信度中。

## Identity（身份）

- **归属**：高德（Amap）搜索技术团队。
- **性质**：面向搜索业务问题排查与经验迭代的 AI 原生数字员工 Agent（交互代号"搜索凌凌漆 007"）。
- **系列定位**：《信息业务 AI Native Builder》系列数字员工篇；与[[gaode-ad-linglingqi|广告凌凌漆]]并列，分别覆盖搜索与广告两条业务线。同系列含总纲篇、交付篇（[[gaode-starship-10x|星舰 10X]]）、现场篇（[[gaode-qingzhou-agent|轻舟 Agent]]）。
- **核心目标**：帮业务提效而非"为了做 Agent 而做 Agent"，让 Agent 承担问题排查、业务分析、需求洞察和主动跟进，把经验经审核进入后续任务。

## Important Facts（重要事实）

- **背景与规模**：搜索是高德最重要场景之一，所有 VOC 需值班同学查清后答复用户。每个 Case 串起数据/召回/排序/Merger/实验/展示等节点，熟手 1-2 小时、新手 1-2 天，经验留在个人脑中。007 接 Case 后自查数据、走链路、给结论，截至 2026 年 10 月累计处理上万条用户提问（按独立消息计），覆盖主搜、车机、详情页、销售、广告等多条业务线。
- **Hermes Agent 基座**：基于 Nous Research 开源的 Hermes Agent（定位具备自我改进能力的个人助手）建设。其通过记忆（MEMORY.md/USER.md 跨会话检索）与技能（任务后写 Skill 文件、后续同类任务加载）反哺。选型时对比低代码平台（异步能力缺失/上下文裁剪靠 Prompt/多轮记忆无法跨会话）与 LangChain/LangGraph（抽象层级低需自行组装），选 Hermes 求"开箱即用 + 可快速组装上线"。
- **三处不匹配与跟随策略**：Hermes 面向单用户设计（多用户需额外数据隔离）、大量本地文件读写假设单实例（多机部署中间文件跨机丢失）、SQLite 大流量写入有上限。策略是跟随社区版本演进、优先吸收上游能力，仅框架问题明确影响业务时才在框架层干预（升级 v0.12.0 启用 steer 模式，解决"连续第二条消息打断上次处理"，未自行改造框架）。
- **按需取证**：归因效果取决于能否获得与当前请求对应、可核验、足够完整的证据；证据不足再强模型也靠猜，证据非越多越好（无关数据引噪声、超预算被截断、越权数据合规风险）。原则是能拿一手数据不用加工过的、用数据说话不靠猜。已接入上百数据源，覆盖引擎/日志/在线离线存储/配置/实验/代码/业务接口/协作平台全链路。
- **取证四步案例**：用户反馈"POI 搜不出来"，四步收敛——queryPoiDetail 确认数据态正常、simulateAppHomeSearch 用真实参数复现拿召回列表、slim_trace 确认目标 POI 不在召回、spEngineDebug 确认召回/重排/final 各阶段均无位次。结论定位到召回链路，但**不等于查明根因**，建议"转引擎团队按此证据继续排查"而非"已定位根因"。
- **自进化四段链路**：为保证"审核前不生效"，拆成四段——候选生成（任务后异步提取经验，写独立 Git 分支）→隔离（运行版只从主分支拉取，未合并候选对线上不可见）→审核（定期 Review 差分，判断可泛化性/证据充分性/是否带偏决策）→发布回滚（合并即生效、可追溯、异常整体回滚上一 tag）。同主题候选审核前先聚类去重。**解读**：关注候选经验经审核合并的比例及复用时是否真提升归因准确率，而非产出量本身。
- **一正一反案例**：正——POI ID 格式陷阱（用户把 B0 写成 BO），经验沉淀成结构化 Skill，审核合并后为同类问题提供先校验 ID 格式的线索（是否适用仍结合本次输入确认）。反——模拟 APP 搜索工具失败时 Agent 改用浏览器访问 amap.com 拿 PC 端结果判断，但 App 与 PC 搜索逻辑完全不同、PC 结果不能作依据，该经验在人工审核被取消。
- **经验治理原则**：**错误经验混入知识库污染之后所有类似决策，比没有经验更糟**；人工审核不能沦为橡皮图章，自动化替掉重复劳动但替不掉关键业务判断。工单评论与流转记录先作线索，须结合最终处理结果与证据核验后才进经验候选。
- **知识库路径**：007 不走自上而下收集文档切片向量化，而是自下而上以每日自进化经验为补充；经验有两态（候选池→审核发布），已发布经验复用时仍须按当前版本与数据重新核验，不替代权威业务规则。特点是新鲜、有场景（未被调用不入集）、有覆盖。
- **从排查到处置与系统机会**：单点问题从"查到"到授权范围内直接发起处置（风控解封/标签权重调整工单，但提交只证明动作发起不证明问题解决）；共性问题定期聚类归因提炼产品优化点，按四阶段跟踪（已形成建议→已创建需求→已开发→已上线并验证），仅第四段计入有效产出。
- **底座复用**：除 Case 排查外，自发用于新人熟悉业务（带真实代码位置/配置出处/数据通道的解释）、产品逻辑追溯（从产品逻辑追到引入提交与受控参数）、销售提效（辅助排查广告投不出去因素）；三场景提问方式与输出形态不同，复用同一套数据接入与业务 Skill。

## Relationships（关系）

- **与广告凌凌漆**：同属数字员工篇姊妹实践，[[gaode-ad-linglingqi|广告凌凌漆]]聚焦广告工程任务执行与可信验收（Personal Dev、CodeGraph、Dev Loop），[[gaode-search-linglingqi|搜索凌凌漆]]聚焦搜索问题归因与经验自进化，共用"数字员工"定位但业务线与机制侧重不同。
- **与轻舟/星舰**：同属高德 AI Native Builder 系列，[[gaode-qingzhou-agent|轻舟]]与[[gaode-starship-10x|星舰 10X]]聚焦交付与工程实现，凌凌漆聚焦问题排查与经验沉淀，三套 Agent 共用业务知识、工具接入与云真机等支撑能力。
- **与 Agent 记忆系统**：007 的自进化经验（候选池→审核发布、复用时重新核验）是 [[agent-memory-system|Agent 记忆系统]]"记忆积累≠能力积累、反馈先判适用范围"原则的工程实例；Hermes 的 MEMORY.md/Skill 文件机制与之呼应。
- **与证据边界**：按需取证、证据可回溯、结论不越界（"定位到召回链路≠查明根因"）印证 [[ai-coding-evidence-boundary|AI 编码的证据边界]]。
- **与验收 Agent**：007 的处置动作须审核通过才执行、提交只证明发起不证明解决，与 [[acceptance-agent|验收 Agent]]"研发验收通过≠交付完成≠效果确认"同向。
- **与 AI 原生 SDLC**：把数据接进来让回答有据可查、把经验审严让知识不被污染，是 [[ai-native-sdlc|AI 原生 SDLC]] 在数字员工侧的落地。

## Current Understanding（当前理解）

搜索凌凌漆的核心变化不是更强的模型或更巧的框架，而是把精力花在两件事上：**把数据接进来，让回答有据可查；把经验审严，让知识不被污染**——后者更重要。**解读**：其自进化机制的关键不在"怎么学"而在"怎么审"，错误经验一旦混入知识库污染的是之后所有类似决策，故人工审核不能沦为橡皮图章。007 的知识库路径（自下而上、以可调用经验为补充）是对传统自上而下文档向量化路径的补充，而非替代权威业务规则；其价值主张是"稳定提高归因准确率与经验复用质量"，而非单纯处理工单数量。
