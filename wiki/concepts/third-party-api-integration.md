# 第三方接口对接（Third-Party API Integration）

## Definition（定义）

B 端系统对接外部供应商接口（支付、电子发票、电子签章、征信、医保、物流轨迹、短信认证等）的完整工程与产品方法论。核心主张：接口对接的完成标准不是"联调通了"，而是"异常发生时业务还能被兜住"——PM 是第三方接口项目的业务负责人，对需求边界、字段契约、异常兜底、对账机制负责，而非传话筒。

## Why It Matters（为什么重要）

B 端系统越来越依赖外部接口，但接口对接的典型失败模式是"整理一份需求文档交技术联调"，上线后业务数据对不上、回调丢失、重复扣款、对账差异无人兜底。外部接口的不确定性（掉线、变更、限流、脏数据）必须由 PM 用明确产出物压成确定性：每个环节有产出物、每个异常有兜底策略、每笔数据有对账基准。

## Core Characteristics（核心特征）

1. **五阶段九要素框架**：五阶段 = 需求与边界评估 → 供应商选型与商务评审 → 方案设计与字段映射 → 联调与验收 → 上线与运维；九要素 = 业务场景、数据范围、字段标准、调用频率、鉴权方式、异常码、重试策略、对账机制、退出机制，贯穿始终。
2. **需求边界先于接口调用**：需求阶段必须回答触发场景、调用量级、失败兜底、幂等要求、数据敏感度、内部改造范围；产出接口需求评估表与业务流程图（如 ERP 发票场景：重复发票拦截、月末峰值、异常进人工审核队列、每日对账文件）。
3. **字段映射表是三方契约**：九列结构（源字段/目标字段/类型/长度/必填/默认值/清洗规则/示例值/备注），业务、技术、第三方三方对账共用；长度不匹配（String(64)→String(32)）需预设截断规则。
4. **状态码映射与未知兜底**：第三方状态码与内部状态建立映射表；未知状态码进入待人工确认，不能直接失败；回传时间口径（第三方时间 vs 内部接收时间）必须在设计文档规定。
5. **联调验收面向异常**：沙箱、Mock、异常注入、对账、性能抽样、安防验证；验收模拟失败/重复创建/回传乱序/地址过期/格式错误等异常路径，而非只走一遍正常调用。
6. **对账逐笔而非总额**：按流水号逐笔核对，区分四类差异（我方有他方无/他方有我方无/金额不一致/状态不一致），差异进差错处理流程并设定处理时效。
7. **熔断降级保核心流程**：外部依赖超时或错误率达阈值时降级使用本地默认规则；接口版本号管理+变更通知机制+上线前回归。
8. **退出机制与进入机制同等重要**：供应商评审必含退出机制，避免单一外部依赖锁死业务。

## Structure（结构）

五阶段产出物链：

| 阶段 | 产出物 | 关键动作 |
|---|---|---|
| 1 需求与边界评估 | 接口需求评估表、业务流程图 | 触发场景/量级/兜底/幂等/敏感度 |
| 2 选型与商务评审 | 接口选型对比表、安防合规清单 | SLA/限流/费用结构/退出机制 |
| 3 方案设计与字段映射 | 字段映射表、接口时序图、异常处理方案 | 九列映射/状态码映射/未知兜底 |
| 4 联调与验收 | 联调用例、验收报告、上线 checklist | 沙箱/Mock/异常注入/安防验证 |
| 5 上线与运维 | 运维手册、对账机制、应急预案 | 监控告警/重试熔断/差错处理/变更通知 |

## How It Works（运作方式）

接口生命周期：业务触发场景澄清（阶段 1）→ 供应商能力与商务条款评审（阶段 2）→ 字段级契约冻结（阶段 3，映射表三方签字）→ 沙箱联调与异常注入验收（阶段 4，异常路径全部通过才算验收）→ 上线后监控指标、告警阈值、日志留痕、重试熔断、每日对账、差错处理、版本变更通知（阶段 5）。外部依赖故障时：重试→熔断→降级本地默认规则，业务主流程不被拖垮。

## Relationships（关系）

### Related Concepts（相关概念）

- [[remote-call-governance|远程调用治理]]——区分：本文是 PM 主导的外部供应商接口对接（含商务/契约/对账），remote-call-governance 聚焦服务间内部调用的技术治理（超时/重试/熔断实现）
- [[retry-governance|重试治理]]——九要素中"重试策略"的展开：重试次数、间隔、幂等要求需在需求阶段定义
- [[idempotency-design|幂等设计]]——重复扣款、重复创建等风险的兜底机制，接口对接的强制评估项
- [[finance-reconciliation-design|财务对账设计]]——逐笔对账与差错处理时效是本文阶段 5 的核心产出

### Dependencies（依赖项）

- 依赖供应商提供完整错误码文档、沙箱环境、变更通知机制
- 依赖内部对账能力（按流水号逐笔核对）与差错处理流程

### Distinctions（区分）

- 第三方接口对接 vs 内部服务集成：前者有外部商务主体、SLA、费用结构、退出机制等非技术维度，后者是内部契约。
- 接口对接 vs 接口联调：对接覆盖需求→运维全链路，联调只是其中阶段 4 的一个动作；"联调通了"不等于"对接完成"。

## Open Questions（开放问题）

- 九要素的量化标准（限流阈值、重试次数、熔断错误率阈值、对账时效）原文未给数值，需结合供应商文档与行业实践补充。
- 多供应商并存时的路由与切换策略（短信多通道切换仅举例）未展开。
- 数据出境/敏感数据（身份证、工资、社保基数）的加密与留存合规细节未涉及。
