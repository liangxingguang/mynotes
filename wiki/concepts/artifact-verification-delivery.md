# 产物核验与独立交付

## Definition（定义）

Agent 任务系统「核对与移交」阶段的设计模式：产物核验输入由原始有效要求、指定产物的可读取事实与检查问题共同组成（不能只来自执行模型的概括）；确定性读取与语义核验分工；交付入口独立于模型最终回复——运行时自行检查允许目录内的文件并构造可打开入口。源自 Codex 桌面客户端 Harness 实践（系列第六篇）。

## Why It Matters（为什么重要）

执行模型的任务概括可能遗漏要求，核验若以同一份概括为准，执行与检查会共享同一个错误。模型最终回复也可能失败（截断、调用失败），若文件发现完全依赖这段文字，用户会失去已生成的成果。E2 实测两类典型失败：核验环节把 Word 汇总表要求套到 Excel（跨文件误修，破坏「首表为发票明细」原要求）；三份文件内容合格却没有形成交付链接，任务停在 ready。

## Core Characteristics（核心特征）

1. **核验输入三组成**：原始有效要求 + 指定产物的可读取事实 + 检查问题。确定性读取（表头、行数、公式、缓存值、Word 表格结构）由程序以只读方式完成（不启动 Office、不重算、不改写文件）；语义对应关系由模型核验；文件过大、依赖缺失或读取异常时返回未知——检查只覆盖被读取范围，未知结果不能自动归为通过。
2. **返修反馈契约**：一条返修反馈关联具体要求、具体产物与检查证据（如「说明文档缺少汇总表」→ 修复目标就是说明文档）；不能概括成「增加汇总信息」再让执行模型自行挑选文件；修改后既要检查缺口，也要检查原先已满足的条件。
3. **核验预算属于执行架构**：预算须覆盖探索、工具执行、核验与收尾。输出额度耗尽只剩推理片段而无结论时，上层记录「核验未完成」——不能解释为默认通过，也不应包装成业务失败的具体原因。E3 实测：输出上限 1,600 tokens 时两次均被长度截断、结论为空；保留相同模型/消息/温度、提至 4,096 tokens、截止时间 60→120 秒后，错误文件被拒绝（指出 Word 缺表与 Excel 缓存为空）、正确文件通过，两次均有完整结论。
4. **核验服务返回契约**：需要返回完成状态、判断结果与检查范围，而不能只提供 pass 布尔值；上层据此区分继续检查、限定返修与停止等待，避免把服务自身失败误用为业务结论。
5. **交付入口独立**：运行时依据声明产物记录检查允许目录内的文件并构造可打开入口，只收集本次声明产物（不扫描整个工作区，避免旧文件/上传资料/临时结果造成来源误认）。文件存在、非空、哈希可读说明「可取得」；内容是否正确需另行核验。E3 实测：对三份内容合格文件做只读回放即返回三个入口，上游模型调用为零，原文件与原任务数据库哈希均未变化。
6. **核验器需校准**：至少需要已确认合格产物与带已知缺陷产物两组样本，分别记录漏检率（错误产物被放行数÷错误产物总数）与误拒率（合格产物被判失败数÷合格产物总数）；缺少某类样本时对应指标不可计算，不能填零。

## Structure（结构）

产物核验分工（三层）：

- 程序确定性读取：文件结构与明确数据（表头、行数、公式、缓存值、Word 表格结构）。
- 模型语义核验：较难用固定规则描述的对应关系与文字含义。
- 返修回路：检查缺口 → 反馈（要求+产物+证据）→ 限定返修 → 复查缺口与已满足条件。

交付链路：声明产物记录 → 文件检查（目录、存在、非空、哈希）→ 入口构造 → 用户取得。原任务保留自己的失败或待确认状态，交付入口不改变任务终态。

## How It Works（运作方式）

限定返修对象收窄判断错误影响的范围，但核验器本身仍会漏判、误判或没有结论，因此需要正确文件与错误文件组成的对照样本，不能只用成功生成的任务评价它。核验范围可随任务风险变化：确定性表格字段先由程序读取，文字与业务解释交给模型；涉及外部写入或高影响决策时可能需人工确认；普通问答不必强制送入完整文件验收流程。返修次数受预算与实际进展限制——重复返回同一缺口而文件无变化时，继续循环未必增加成功机会，停止时保留可用成果与未解决问题，使后续执行能从具体缺口继续。

## Relationships（关系）

### Related Concepts（相关概念）

- [[agent-state-separation|Agent 状态分离]]：产物核验是三态之一（另两态为执行状态与操作状态）；独立交付入口是「文件已完成但交付未结束」状态的外部形态。
- [[agent-evaluation|业务 Agent 全生命周期评测]]：两者都反对以总分掩盖关键错误、主张分项判定；核验器正反例校准（漏检率/误拒率）与该页复合裁判、黄金集反哺同族。
- [[durable-execution|持久执行（Durable Execution）]]：交付入口的只读回放是对既有成果的投影而非重新执行——印证「补交付入口可以与重新生成文件分离」。

### Dependencies（依赖项）

- 产物声明机制（本次任务应产出什么）——入口收集与范围限定的前提。
- 只读文件事实读取能力（Office 解析库只读提取）——确定性读取的前提。

### Distinctions（区分）

- 与「从最终回复提取链接」的区分：后者依赖模型文字、截断即丢失；本页入口由运行时依据产物记录构造，模型回复只是解释而非依赖。
- 与端到端打分的区分：核验是任务内的控制回路（判断→返修），不是评测打分；评测标准见 [[agent-evaluation|业务 Agent 全生命周期评测]]。

## Evolution（演进）

## Open Questions（开放问题）

- 核验预算投入与任务价值的权衡如何量化？信源只给「留足核验输出与等待空间」的方向性结论，未给公式。
- 语义核验的误判率随业务领域差异大，正反例校准样本集的泛化能力未经验证。
