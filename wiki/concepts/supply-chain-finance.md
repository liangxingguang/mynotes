# 供应链金融（Supply Chain Finance）

## Definition（定义）

供应链金融是围绕核心企业信用流转的融资机制设计：把核心企业的信用沿供应链传递给上下游中小供应商，让供应商凭真实贸易背景（应收账款等资产）提前获得回款，资金方在风控前提下放款。B 端 PM 的工作不是把线下流程搬到线上，而是设计一套让信用在链路上流动、让四方利益对齐的系统机制。

## Why It Matters（为什么重要）

供应链金融项目天然三方拉扯：业务方要线上化、资金方要控风险、核心企业要少添麻烦。若 PM 只当传话筒（写需求文档交技术联调），上线后必然出现重复融资、确权拖延、清分对不上账。系统价值不在页面，而在确权、放款、风控、清分等关键节点的时效与自动化能力——这决定了融资时效和资金方信任。

## Core Characteristics（核心特征）

1. **本质是信用流转而非借贷**：供应商给核心企业供货后有账期（案例 60 天），缺钱想提前回款；资金方放款前提是应收账款真实存在且核心企业到期付款。判断一个供应链金融项目是否成立，先看信用在链路上是否可验证、可流转、可追溯。
2. **四方角色诉求互斥，需系统对齐**：供应商（快速拿钱/流程简单，抗拒确权慢资料多）、核心企业（稳定供应链/不加风险，抗拒确权占信用额审批链复杂）、资金方（业务增长/风险可控，抗拒贸易背景造假与重复融资）、平台运营（流程可追踪/异常可处理，抗拒线下材料多状态不透明）。
3. **防重复融资是资金方核心风控**：通过中登登记（放款前自动完成中登网登记）+ 发票验真（对接税务数据校验发票状态）双重拦截，是案例中重复融资风险得到有效控制的机制。
4. **六中心架构，模块是承载状态的容器**：企业/资产/确权/风控/资金/报表六中心；架构设计顺序是先把"资产状态"想清楚再拆模块。
5. **状态机是骨架，每状态四件事**：主流程 待提交→待确权→已确权→待放款→已放款→已结清，异常分支 确权驳回/验真失败/放款失败/逾期/部分回款；每个状态定义可见角色、可执行动作、权限控制、超时机制与通知策略（待确权 24h 提醒、72h 升级）。
6. **指标前置到需求阶段**：六项硬指标（融资申请通过率/确权时效/放款时效/重复融资拦截率/逾期率/清分准确率）每个都对应一个系统能力，不是上线后才看。
7. **案例量化成果**：确权时效 3 天→4 小时、融资申请到放款 5 天→T+1、重复融资风险通过中登登记+发票校验控制。

## Structure（结构）

应收账融资系统六中心：

| 中心 | 职责 | 关键能力 |
|---|---|---|
| 企业中心 | 入驻/实名认证/授信额度/角色权限 | 四方角色管理 |
| 资产中心 | 应收账/发票/合同/发货单/贸易背景材料 | 资产归集与存证 |
| 确权中心 | 核心企业确权待办/授权链/结果回传 | 在线确权、待办推送 |
| 风控中心 | 发票验真/中登登记/黑名单/重复融资校验 | 放款前拦截 |
| 资金中心 | 放款指令/还款计划/清分规则/对账 | 到期自动清分 |
| 报表中心 | 投放金额/逾期率/确权时效/放款时效/余额 | 指标监控 |

资产状态机：

```
主流程：待提交 → 待确权 → 已确权 → 待放款 → 已放款 → 已结清
异常分支：确权驳回 / 验真失败 / 放款失败 / 逾期 / 部分回款
```

## How It Works（运作方式）

供应商上传贸易背景材料 → 资产中心归集 → 风控中心发票验真+中登登记防重复融资 → 确权中心推送核心企业确权待办（授权链校验，24h 提醒/72h 升级）→ 确权完成转待放款 → 资金方放款 → 到期核心企业付款 → 资金中心按规则自动清分给资金方 → 报表中心统计时效与风险指标。每个状态的可见角色、动作、权限、超时通知由状态机统一驱动。

### Dependencies（依赖项）

- 依赖核心企业确权授权链（不能一个号全通过）与税务发票验真接口
- 依赖中登网登记能力做重复融资拦截

### Distinctions（区分）

- 供应链金融 vs 普通信贷：前者依托核心企业信用与贸易背景资产流转，后者依赖借款人自身资信。
- 供应链金融 vs 单纯线上化：前者要处理线下差异（确权形式、盖章、口头确认），后者假设流程可原样迁移。
