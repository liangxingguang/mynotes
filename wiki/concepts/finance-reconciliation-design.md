# 财务对账与异常冲正系统设计

## Definition（定义）

财务对账是 B 端系统验证「业务单、内部资金流水、外部渠道流水」三条线一致性的过程；任何一笔资金收付都同时在三条线产生记录，对账即发现不一致并归类、定位、处理。异常冲正是对账差异处理的核心手段——不删除原记录，而是生成可追溯的反向记录。两者共同构成 B 端财务系统的资金安全保障机制。

## Why It Matters（为什么重要）

- 对账是交易、支付、结算、清分、SaaS 订阅等系统的硬骨头，抽象、跨系统、强财务属性。
- 交付的系统若不懂资金收付与异常冲正，上线后会被财务追着问：「这笔长款哪来的？那个负流水为什么没有冲正单？」
- PM 的核心能力不是算得快，而是定义清楚：谁和谁对、按什么对、差异谁负责。
- 对账系统真正要处理的不是「一致」，而是「不一致」——差异处理闭环才是产品价值所在。

## Core Characteristics（核心特征）

1. **三角模型**（信源二）：业务单（订单/应收单/应付单/报销单/结算单）、内部资金流水（余额/保障金/红包/减免券/虚拟账户）、外部渠道流水（商行/第三方支付/清算机构/医保结算平台）。任何一笔资金收付同时在三条线产生记录。
2. **七层架构**（信源一）：数据源层 → 采集层 → 标准化层 → 匹配层 → 差异层 → 处理层 → 报表与凭证层。数据源含业务库/资金网关/银行/渠道/ERP/发票/HIS；采集用 API/文件/SFTP/email/RPA。
3. **差异三类型**：长款（渠道有流水、业务无单据）、短款（业务有单据、渠道无流水）、不一致（金额/状态/手续费/时间不一致）。
4. **差异处理闭环**：数据获取 → 标准化 → 匹配 → 差异处理 → 复核 → 关账。把差异规则化交给规则引擎，而非「自动匹配失败就人工调账」（会越对越乱）。
5. **容差规则示例**：物流运费对账——单笔差异 <3% 且单日累计 <500 元自动通过，超容差才进人工调账（信源二）。
6. **冲正不删除原记录**：冲正单必须关联原单、说明原因、携带审批人与时间；原单一旦生成不可修改。
7. **红冲 vs 蓝冲**：红冲用负数冲销原金额保留原始记录（财务账务调整）；蓝冲生成金额相等方向相反的新交易（资金流水层反向）。
8. **冲正四原则**：原单不可变、冲正单可追溯、幂等控制（同一原单同一原因只能生成一笔成功冲正单）、资金保障优先（发起前校验余额/渠道状态/风险策略）。
9. **七行业对账重点**：ERP（应收应付核销/账龄）、EHR（薪资发放失败重发/重复发放）、OA（报销支付失败冲正重发）、车贷金融（代扣超时/重复扣款/逾期补扣防重复）、物流（承运商结算容差）、CRM 电商（订单回款/减免券/退款与冲正区分）、业务中台用户中心（余额/积分/保障金流水准确）。

## Structure（结构）

对账中心数据模型至少 7 张表（信源二）：业务单、支付单、渠道流水、对账单、差异明细、冲正单、调账单。每张表必须记录创建时间、更新时间、处理人、状态、关联单号。

接口 6 类（信源二）：渠道对账单下载/上传、解析与标准化、自动匹配、差异处理、冲正申请/确认/查询、调账单生成。

页面三个工作台（信源二）：对账结果工作台（按日期/渠道/业务线展示匹配率/差异金额）、差异处理工作台（差异明细+自动规则建议+人工处理）、冲正审批工作台（冲正申请/资金影响/审批状态）。

## How It Works（运作方式）

### 对账闭环

数据获取 → 标准化（字段映射/状态映射/时区/币种/精度）→ 匹配（主键/金额/时间窗/容差/模糊匹配）→ 差异处理（差异池/原因码/优先级/责任方）→ 复核 → 关账。产出对账报表、结算单、凭证、审计日志。

### 冲正流程（商户代扣案例，信源二）

扣款成功但回调超时：先调用渠道查询接口 → 查到成功则更新状态 → 查询无结果或超时再发起冲正 → 冲正成功后才允许下一笔代扣。直接标记失败再扣款会造成重复扣款。冲正单是防止资金风险的关键。

### 时间差 vs 冲正

CRM 案例：支付宝支付订单已成功但财务未核销，因渠道流水 T+1 到账。属「时间差」，处理方式不是冲正而是挂账等待下一轮对账自动匹配。

### 退款 ≠ 冲正

退款是业务结果，冲正是交易层面反向；冲正成功后可能触发退款，也可能仅调整账户流水。

### PM 实操 SOP 九步（信源一）

定目标 → 盘数据 → 标准化 → 设规则 → 分差异 → 做核销 → 出报表 → 加监控 → 灰度上线（先跑历史数据→并行→切主流程）。

### Dependencies（依赖项）

- 对账匹配依赖主键统一（订单号/流水号/合同号不能混用）
- 冲正依赖状态机定义清晰（待支付→支付中→成功/失败/已冲正）

### Distinctions（区分）

- 对账 vs 对账系统：对账是验证一致性的动作，对账系统是支撑该动作的七层架构+闭环。
- 冲正 vs 退款：冲正是交易层反向（技术机制），退款是业务结果（业务动作）。

- 2026-11-04：信源一（对账系统设计框架，七层架构+6案例+SOP）+ 信源二（底层逻辑+冲正+PRD状态机）合并为一概念页。两信源互证：信源一补七层架构与SOP，信源二补三角模型/冲正四原则/7张表/三工作台。

## Open Questions（开放问题）

- 七层架构与三角模型的映射：三角模型是数据源层内的「三线一致性」视角，七层是工程分层，两者非互斥但未在信源中显式对应。
- AI 智能对账（信源一案例7）仅描述 NLP/大模型抽取+异常检测+人机协同，未给落地阈值与评估基线，待后续信源补充。
- 跨币种/税额对账的具体规则未展开，信源仅提及「币种、税额」为差异维度。
