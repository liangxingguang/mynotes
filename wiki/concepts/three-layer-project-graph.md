# 三层互索引项目图谱

## Definition（定义）

三层互索引项目图谱是腾讯云数据库团队在研发 Loop 中构建的、用于单仓和跨仓的三层关联知识图谱。三层分别是：工程事实（静态的符号/字段/接口及跨仓契约关联）、项目语义（结合工程分析与 LLM 提取的功能职责/业务概念/跨仓映射与约束，本体体现在此层）、错误与经验（bug_fixed，将历史 Bug 整理成经验挂到前两层节点）。三层之间双向互索引，模型可从任意一层进入（信源 2026-11-20）。

## Why It Matters（为什么重要）

Agent 读懂局部代码不等于理解项目。模型能读懂代码结构，却可能没有把对象、状态或字段的项目含义理解准确，这是团队实践中观察到的返工卡点。三层图谱把工程锚点、语义解释、历史反例分开组织并互索引，让 Agent 从代码找到经验、从经验反查实现，再通过概念和约束判断是否适用，从而减少重复理解与相同误判（信源 2026-11-20）。

## Core Characteristics（核心特征）

1. **三层分工明确**：第一层工程事实偏静态（函数/类型/字段/接口及跨仓契约，类似 CodeGraph 但含跨仓关联）；第二层项目语义偏动态（随新材料和理解修正而更新，本体体现在此层的概念与约束表达）；第三层 bug_fixed 挂历史经验，区分"一次事件"与"可复用经验"（信源 2026-11-20）。
2. **跨层双向互索引**：模型可从任何一层进入——有明确符号从工程层、纯业务需求先找概念、遇故障先查经验，不固定执行"先读代码再读语义最后读历史"的顺序。"代码实现某项约定"可反查为"约定由哪些代码实现"，但语义关系本身不对称（信源 2026-11-20）。
3. **本体不必成为第四层**：本体体现在第二层概念与约束表达，以及跨层关系对实现、经验、证据角色的区分。第一层提供工程锚点，第三层提供历史反例，两者帮助修订项目语义（信源 2026-11-20）。
4. **渐进式披露控制信息量**：先给关联理由/风险摘要/适用范围，再展开触发条件与检查方法，最后读完整差异/对话/运行证据。关键前提（版本、权限、项目范围）必须随摘要出现，不能藏到最后一层（信源 2026-11-20）。

## Structure（结构）

三层结构（信源 2026-11-20）：

| 层次 | 定位 | 内容 | 特征 |
|---|---|---|---|
| 工程事实 | 偏静态 | 函数/类型/字段/接口及使用者关系，含跨仓关联 | 类似 CodeGraph，跨仓边须经 API/消息/Schema 契约核对 |
| 项目语义 | 偏动态 | 功能职责/业务概念/字段含义/跨仓映射/约束 | 本体体现在此层，LLM 候选关系不能仅凭语言流畅升级为项目事实 |
| bug_fixed | 经验层 | 历史 Bug 整理成经验挂到前两层节点 | 区分"一次事件"与"可复用经验"，渐进式披露 |

四类记忆资产（Chat Memory、Wiki、CodeGraph、Skill）与三层图谱是两个维度：前者侧重材料形态与用途，后者侧重知识间怎样关联和访问，不是七类平行资产（信源 2026-11-20）。

## How It Works（运作方式）

跨仓场景示例（信源 2026-11-20，解读）：假设配置约定为"未传策略字段用默认配置，显式传空列表清空限制"，请求失败重试后用户选择丢失。从字段出发，工程层引导查看仓库 A 请求解析、跨仓消息契约、仓库 B 持久化与重试读取路径；语义层说明"未传"与"显式空"表达两种意图，传递与重试都要保留区别；历史经验若记录过适用条件相同的默认值覆盖问题，提供优先检查的候选解释。随后仍需验证：保存时是否已丢失区别、重试后是否改变，由当前代码和实际观察决定结论。

## Relationships（关系）

### Related Concepts（相关概念）

- [[ontology|Ontology]]：本体体现在第二层的概念与约束表达，以及跨层关系对实现、经验、证据角色的区分。
- [[recursive-self-improvement|递归自我改进（RSI）]]：三层图谱是 RSI 在研发场景的载体——本体修订、经验挂接、策略优化分别对应不同改进层次。
- [[agent-memory-system|Agent 记忆系统]]：四类记忆资产是图谱的原料来源，三层图谱是这些资产如何关联和访问的组织方式。

### Distinctions（区分）

- **三层图谱 vs 四类记忆资产**：四类资产（Chat Memory/Wiki/CodeGraph/Skill）侧重材料形态与用途，三层图谱侧重知识间怎样关联和访问，是两个维度，非一一对应。
- **工程事实层 vs CodeGraph**：工程事实层类似 CodeGraph，但还包含跨仓关联，跨仓边须经 API/消息/Schema 等契约核对，不能仅凭同名符号连边。
