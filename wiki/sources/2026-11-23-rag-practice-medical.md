# RAG 技术实战：从微调召回到精排的完整链路

## Overview（概览）

微信公众号 RAG 系列的实战篇，以医疗问答为场景走通 RAG 完整链路。文章从基础问答对（FAQ）架构的召回痛点切入，依次讲数据准备（用大模型把非结构化文本拆成问答对、Bert 微调造样本）、双塔召回模型（DSSM）、索引与检索（Faiss 写索引、LLM 扩写 query 多路召回）、精排（Bert 二分类打分、阈值过滤、多路候选累加排序），最后对比 RAG 与 SFT 的适用边界并讨论多轮问答的上下文处理。核心结论是"召回+排序+大模型归纳"三段式，且每一环换回原生模型效果立即变差。附 OpenAI 数据量化：原生模型 45% → 召回提升 65% → 重排 85% → 大模型归纳 98%。

## Key Facts（关键事实）

- **能力定位**：大模型能力分两套技术——推理（靠思维链）与知识（RAG 补充）；基础架构是问答对知识库向量化检索，痛点是召回数量与误召回难以控制。
- **数据准备**：用大模型把非结构化文本拆解生成问答对；原生 Bert 是泛常识模型、向量不宜直接用于专业域召回，需自采数据微调——同病句内打乱配对做正样本（每病约 3000 对），跨病随机组合做负样本（正样本的 2–4 倍），样本量需过万。
- **双塔召回（DSSM）**：两塔共享参数保证向量同空间，余弦相似度经 sigmoid 转 0–1，温度系数放大分数以便收敛；冻结前层只训练最后一层（数据量大再加层）；只保存 Bert 不保存 DSSM，句子向量全部离线预计算。
- **索引与检索**：向量归一化后（768 维）写入 Faiss 索引（分区加速，只算同区相似度）；在线侧先用 LLM 扩写 query（随机采样保多样性），每路 Faiss 召回 30 个候选。
- **精排（rank）**：双塔无信息交互，用 Bert 将 query 与候选句拼接做二分类打分（截取 200 字内），低于阈值过滤；多路召回的重复候选按"次数/分数"累加排序取 Top；可用关键词贡献过滤乱问，排序严格时召回可放宽。
- **效果验证**：OpenAI 数据——原生模型 45% 准确率，召回提升到 65%，重排 85%，大模型归纳 98%；召回与排序换回原生模型效果立刻变差。离线用大模型（如通义 14B）、在线用小模型（如 ChatGLM 6B）控成本。
- **RAG vs SFT**：RAG 用动态数据可每日更新、外挂知识、幻觉少、可逐阶段 debug；SFT 影响文风、静态数据更新贵；专业问答优先 RAG，写作风格用 SFT。
- **多轮问答**：前几轮知识全拼入会因上下文过长忽略本轮问题，需判断上下文是否关联（模型二分类自动切分）或用大模型提取摘要；提示词稳定性弱——demo 看上限，生产看下限，慎用。

## Important Claims（重要论断）

### 召回+排序+大模型归纳是三段式递进

每一环有独立贡献且不可跳过：从原生模型到加召回是第一步（45%→65%），召回之上加重排再一步（65%→85%），最后大模型归纳才到 98%；换回原生模型效果立刻变差，证明每段的技术都有实质贡献而非冗余。

### 专业域必须自采数据微调

原生 Bert 的向量是泛常识表示，不适合医疗等专业域直接召回；必须自采数据构造正负样本微调，使向量空间适配领域语义——这与 [[rag]] 中"嵌入模型硬约束"（建库与问答须同模型）互为印证：不仅要求模型一致，还要求模型与领域匹配。

### RAG 与 SFT 改的变量不同，专业问答优先 RAG

RAG 改的是"依据哪些事实说"（动态数据、可每日更新、外挂知识、幻觉少、可逐阶段 debug），SFT 改的是"怎么说"（影响文风、静态数据更新贵）。专业问答场景知识更新频繁且要可溯源，优先 RAG；写作风格等行为模式场景用 SFT。

### 多轮问答的上下文管理是独立难点

多轮场景下，全量拼接历史知识会因上下文过长而忽略本轮问题；需先判断上下文是否关联（模型二分类自动切分）或用大模型提取摘要压缩，而非简单拼接。提示词在 demo 中表现好不等于生产稳定——"demo 看上限，生产看下限"。

## Implications（影响／启示）

- 专业域 RAG 落地不能跳过数据微调：原生嵌入模型的向量空间与领域语义不匹配，必须自采样本微调才能获得有效召回。
- 精排环节是召回的补充而非替代：双塔模型无 query-doc 交互，Bert 二分类拼接打分弥补这一缺陷，阈值过滤与多路累加是工程上实用的方案。
- 成本控制靠离线/在线模型分层：离线批量处理用大模型保证质量，在线实时请求用小模型控延迟与成本。
- 多轮问答需显式做上下文关联判断或摘要压缩，不能默认全量拼接。

## Limitations（局限）

- 单信源、实战经验总结，无独立实验对照；OpenAI 基准数据（45%→98%）为文中转述，未给出数据集与评测口径。
- 医疗场景的特殊性（专业术语、高准确率要求）可能不完全适用于通用 RAG 场景，结论的泛化性需谨慎。
