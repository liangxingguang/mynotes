# 星舰Cloud Agent：一项研发任务如何在云端运行

## Overview（概览）

微信公众号「高德技术」《信息业务 AI Native Builder》系列交付篇之一。以「读取项目生成报告」任务为例，拆解星舰内部负责云端执行的后台服务 **Cloud Agent**：它为 Agent 安排远程沙箱、启动并管理执行、收集结果交回星舰展示。全文详述架构与职责边界、任务六阶段生命周期、执行结果与交付完整性的分离表达、会话/轮次/执行环境三层管理、四种中断恢复与三种恢复粒度、以及更换引擎的适配层设计。高德技术一手自述，明确标注相关约束为「设计要求」而非已验证能力，单信源，置信度中。

## Key Facts（关键事实）

- **角色边界**：星舰（接收要求、组织工作流、展示结果，不直接承载构建/测试/文件操作）；Cloud Agent（记录任务、安排环境、启动管理执行、收集结果，不替代 Agent 理解项目、不决定业务验收）；沙箱（提供工具/目录/算力，不理解报告结论）；Agent（读项目、调工具、形成结论写文件，不管理平台排队/资源/归档）。
- **主路径**：星舰接收要求 → Cloud Agent 安排执行 → 沙箱中 Agent 读项目写报告 → Cloud Agent 收集报告 → 星舰展示结果。
- **独立沙箱动机**：Agent 的读文件/装依赖/跑构建测试与在线业务服务负载不同，混在业务容器会挤占资源、发布重启中断任务；独立沙箱将实际工作移出业务服务，星舰复用已有沙箱能力而非重建算力平台。
- **任务六阶段**：登记任务（含仓库版本/材料/Agent/工具/时长等执行条件，先存记录再安排执行）→ 申请环境（复用需核对身份/授权/用途）→ 备料（取仓库/放附件/备工具，环境准备与 Agent 工作分开记录）→ 启动 Agent 持续接收过程 → 收回报告（识别本次生成修改的文件）→ 交回结论与文件。
- **执行结果≠交付完整性**：正常结束不等于文件全部交付、也不等于业务验收通过；执行失败但初稿已归档应同时表达「执行失败」+「初稿可下载」；「完成」分引擎结束/归档处理/文件完整/业务验收多层。
- **会话管理三层**：会话（跨多轮持续工作关系）/ 轮次（会话中一条消息及处理）/ 执行环境（沙箱目录工具进程，可保留或回收，与会话记录分离）；进程退出、环境保留、沙箱回收是三个不同动作。
- **中断恢复四情况**：用户关页面（仅展示连接断开，非任务取消）；管理服务重启（新节点先查任务记录再核对现场，管理权接管需回答归属失效/唯一确认/旧节点恢复后哪些操作失效）；Agent 进程退出（按保留材料判断是否续原环境）；沙箱终止（只能靠已存历史/归档/快照重备环境）。区分「连不上」与「已终止」，恢复分接管进程/恢复文件续会话/重新执行三种粒度。
- **引擎适配层**：统一启动/过程输出/正常结束/异常结束/会话恢复五类交互，参数形式不同在适配层转换，引擎只给部分信息时不补造缺失记录；适配层解决「不同 Agent 怎么接入」，不是让所有 Agent 表现一致。

## Important Claims（重要论断）

### 执行结果与交付完整性须分开表达

「部分交付」不必新增为任务状态，而可在交付结果中说明。引擎执行正常结束、成果归档处理结束、交付文件完整、业务验收通过，不是同一个结论；不能用一个笼统「成功」代替三项判断。

### 设计要求 ≠ 已验证能力

涉及请求去重、取消、管理权接管和中断恢复的约束，作者明确标为「设计要求」，不表述为已经验证的能力；文中例子用于解释流程，不是实测案例或可靠性验证结论。

## Implications（影响／启示）

**解读**：Cloud Agent 把「平台管理」与「Agent 执行」分离，星舰不照看远程进程、Agent 不承担平台资源与结果管理，是 [[durable-execution|持久执行]]「框架管从哪里继续、平台管状态保存在哪与由谁继续」分层在云端任务执行的落地。其「执行结果≠交付完整性」「连不上≠已终止」的区分，为云端 Agent 交付的验收与恢复提供了可操作的判断口径。
