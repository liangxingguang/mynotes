# RAG 中的大模型生成：最后一公里

## Overview（概览）

微信公众号「RAG 技术实现全流程」系列第 4 篇（教程式文章）。讲检索之后的"最后一公里"：检索→上下文构建→生成→输出中的**生成环节**。核心立场是大模型在 RAG 中是"智能整合器 + 语言表达器"，与纯大模型问答的区别是严格锚定检索资料而非依赖自身记忆；围绕这一立场展开 Prompt 工程（四原则、动态模板路由、温度调参）、上下文构建（筛选、去重、窗口管理、结构化）、长文本问答（Small2Big）、多文档问答（引用增强）、表格问答、上下文压缩与答案溯源，目标是让模型严格锚定证据、抑制幻觉、可溯源。

## Key Facts（关键事实）

- RAG 整体流程为「检索→上下文构建→生成→输出」：检索负责找证据，上下文构建把证据准备好，生成把证据变成用户可读答案，生成是用户真正接触到的环节。
- 大模型在 RAG 中承担"智能整合器"与"语言表达器"角色，核心能力为理解、整合、生成三项。
- 与"纯大模型问答"的区别：生成答案时严格锚定检索资料，而非依赖模型自身"记忆"，以减少幻觉。
- Prompt 工程四原则：明确角色、限定信息源（仅基于资料回答）、规定输出格式、兜底策略（无证据返回"无法回答"）。
- 进阶要素：动态 Prompt 模板路由（Template Router 按查询类型选择模板）与温度调参——事实型 0.0-0.3、解释/策略型 0.4-0.7、头脑风暴/创意型 0.8-1.0。
- "Lost in Middle"问题：多资料输入时模型易忽略中间信息，原因是对长序列输入注意力分配不均衡；对策为资料排序优化、分段输入、提示词要求全面覆盖。
- 幻觉抑制三管齐下：① Prompt 工程（明确角色、约束与输出格式）；② 上下文构建（重排序、去重、结构化、窗口管理）；③ 溯源与校验（强制标注来源并做答案→证据匹配校验）。
- 上下文构建四大原则：少即是多、上下文=模型的世界、组织结构决定理解力、上下文可追溯性。
- 上下文构建流程：多路召回→初步筛选过滤（关键词、重排序、相似度阈值、相关性判别）→ RRF 精排→去重合并→TOKEN 预算管理→结构化组织。
- 长文本问答的正解是动态分片（chunk size ≈ 256 的平衡点、按文档结构层级解析、分片编号 chunk_idx/chunk_cnt）+ Small2Big 补全——"精准命中靠向量，相对完整靠邻居"。
- 多文档问答：多源检索融合（BM25 + 向量 + RRF）→ 用 `<document X>` 标签包裹并编号的结构化上下文 → 引用增强生成（显式引用或内联引用 `[1]@ref`）；可分文档摘要再全局整合，支持引用链追踪与冲突提示。
- 表格问答：表格解析→结构化文本/摘要→可读文本（Markdown）；文中给出的模型对比结论为 DeepSeek-32B 综合最强、Qwen2.5-32B 稳定、TableGPT2-7B 偏弱（作者引用的第三方评测结论，未经独立核验）。
- 上下文压缩可减少 30%~80% 输入 token，但非必需——先试不压缩能否解决问题，压缩可能带来信息丢失。
- 答案溯源：分离式架构（先生成答案、再独立溯源）；两阶段策略——n-gram 文本匹配召回（相似度超阈值直接返回）→ LLM Rerank 精选最相关出处。

## Important Claims（重要论断）

### 生成环节是 RAG 效果的最终出口

检索、上下文构建的成果最终都通过生成环节交付给用户；生成质量的锚点是"严格锚定检索资料"，而非模型自身记忆（支撑 [[rag]] 的"检索×生成相乘"与"出处可核对"论断）。

### 幻觉抑制须三管齐下

仅靠 Prompt 约束不足以抑制幻觉，需要 Prompt 工程、上下文构建、溯源与校验三层配合（提示词约束、资料锚定、来源校验、LLM-rerank 校验、无证据退回"无法回答"）。

### 上下文质量决定模型"看到什么"

"上下文=模型的世界"——模型回答的依据完全来自上下文，上下文没写的内容模型"看不见"；上下文构建的核心任务是在有限空间内放入最有用的内容。

### 长文本问答不能只靠调参

增大 chunk_size、增加 TopK、后置 rerank 三种传统补救手段各有局限（噪声稀释、开销飙升、仍受窗口上限约束），正解是动态分片 + Small2Big 补全。

### 压缩不是默认动作

上下文压缩能降本提速，但可能丢失信息，应先验证不压缩能否解决问题，再决定是否压缩。

## Implications（影响／启示）

- RAG 系统设计应把"生成环节"当作独立工程对象对待：Prompt 模板、上下文组织、引用与溯源机制是生成质量的三大杠杆。
- 溯源与校验是生成环节的合规刚需：强制标注来源 + 答案→证据匹配校验，可减少虚假引用、满足审计需求。
- 对长文档与多文档场景，检索侧的分片设计（动态分片 + 邻居扩展）与生成侧的引用标注需协同设计。
