# B端权限设计别只控菜单：功能、数据、字段三层拆解

## Overview（概览）

B 端权限设计的方法论文章。主张权限是功能权限（能做什么）、数据权限（能看哪些行）、字段权限（能看哪些列）三层交叉，结合 ERP、EHR、OA、CRM、车贷、物流、HIS 场景拆解三层设计方法，给出三张表产出物（功能权限矩阵/数据权限规则表/字段权限清单）、权限设计 SOP 七步与五条常见坑。

## Key Facts（关键事实）

- **三层权限模型**：功能权限、数据权限、字段权限三层交叉；越权/数据泄露/审计不合规的根源在需求阶段权限边界没画清。
- **功能权限**：RBAC 用户-角色-权限点；角色可继承；权限点拆到按钮级，避免只控到菜单。OA 例：普通员工提交申请+查看本人流程；部门经理加审批通过/驳回；HR 可看全公司考勤但不可编辑。
- **数据权限规则**：全部、本部门及下级、本部门、本人、自定义。案例：CRM 销售员看自己客户/销售经理看团队/财务仅看回款相关；车贷风控专员看本人案件/组长看本组/贷后看逾期；物流仓库管理员看本仓库存/区域经理看区域内所有仓。实现上与功能权限解耦、在查询层注入数据范围条件。
- **字段权限**：列级控制；权限类型分可见、可编辑、加密；敏感字段含薪资、身份证号、手机号、采买价、利润、供应商账户。案例：EHR HR 可见薪资证件号/部门经理仅看绩效职级/员工仅看基础信息考勤；车贷身份证号仅风控与合规见完整值、用户支持看掩码（如 410\*\*\*\*\*\*\*\*\*\*\*1234）；ERP 采买价仅采买经理与财务可见、仓库只看数量库位；HIS 医师看诊疗字段/收费员看费用字段/库房看库存字段。
- **三张表产出**：功能权限矩阵（角色×菜单/按钮）、数据权限规则表（角色×数据对象×数据范围）、字段权限清单（对象×字段×角色×权限类型×加密规则）。
- **SOP 七步**：梳理角色岗位（避免角色爆炸）→列功能点（菜单/页面/按钮/接口）→定义数据范围→标记敏感字段→输出三张表→开发评审与越权测试→上线后权限审计与变更流程（工单+留痕）。
- **常见五坑**：只控菜单不控按钮；数据权限写死在页面换入口绕过；字段只在 UI 隐藏接口返回全字段；角色与权限点绑定太死维护成本高；没有权限审计无法定位。

## Important Claims（重要论断）

### Claim 1：权限问题的根因在需求阶段

系统上线后越权、数据泄露、审计不合规，问题不在代码，而在需求阶段权限边界没有画清。

### Claim 2：前端隐藏不等于权限管控

接口层必须二次校验，否则 UI 隐藏只是视觉安慰。
