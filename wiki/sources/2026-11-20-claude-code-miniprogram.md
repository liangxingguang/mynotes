# 零代码，我用 Claude Code 做小程序（保姆级教学）

## Overview（概览）

一篇面向个人的实操教程：用 Claude Code 从零开发一个微信小程序"保质期管家"（记录物品名称与到期日期，按到期日期排序并显示剩余天数/过期状态）。全文按"环境准备 → 实战开发 → 预览与发布"三段推进，核心方法是在**计划模式**下先出方案、逐项确认，再开始开发。作为单信源教程，数字与流程为作者实操记录，未经独立复验。

## Key Facts（关键事实）

- **环境准备三件套**：① 安装 Claude Code（Mac `curl -fsSL https://claude.ai/install.sh | bash`，Windows `irm https://claude.ai/install.ps1 | iex`），`claude --version` 验证；② 微信公众平台注册小程序并获取 AppID（账号类型选小程序，完成邮箱验证、主体信息与管理员绑定）；③ 安装微信开发者工具（developers.weixin.qq.com 下载对应安装包，用绑定管理员或已添加为开发者的微信扫码登录）。
- **同一项目文件夹分工**：微信开发者工具创建基础项目（开发模式选"小程序"、初始化选"模板"中的 TS + Sass 基础模板，后端选"不使用云服务"），Claude Code 在**同一目录**中启动开发——工具负责运行与查看效果，Claude Code 负责修改代码，改完回开发者工具重新编译即可看到变化。`project.config.json` 是识别项目目录的依据。
- **计划模式流程**：终端按 Shift + Tab 切换模式，直到输入区下方显示 `plan mode on`；粘贴需求后 Claude Code 先读取现有项目结构，给出开发方案，并把需要决策的细节逐项列出确认（本文两问：添加物品的交互形式选"独立添加页"、模板自带演示代码选"清理掉"），在顶部 Submit 处核对选项、选 `Submit answers` 提交后，才整理完整方案。
- **需求描述要点**（原文给出的完整需求模板）：沿用现有模板不引框架、首页展示已添加物品（名称+到期日期+剩余天数，按到期日期从早到晚排序）、提供添加入口、空值提示补全、日期选择器允许选过去日期、剩余天数按本地自然日计算、过期标红+已过期天数、当天到期、剩 1–7 天标橙、超过 7 天正常显示、不能只靠颜色还要文字说明、微信本地存储、明确"本次不做"清单（账号登录/云开发/消息通知），并明确要求"先只输出开发方案，不修改代码，确认后再开发"。
- **确认与开发**：方案符合预期后按回车批准，Claude Code 退出计划模式以自动模式开始开发，结束后给出完成摘要（修改了哪些文件、实现了哪些功能）。
- **预览与发布收尾**：开发者工具编译预览 → 顶部"真机调试"生成二维码，用有权限的微信扫码在手机上检查（电脑正常不等于手机正常）→ 顶部"上传"填版本号和项目备注 → 公众平台版本管理核对开发版本 → 设为体验版并添加体验成员 → 首次发布前完善名称/头像/简介/服务类目并完成小程序备案 → 提交审核（填写功能说明、选择功能页面）→ 审核通过后在版本管理点击"发布"，显示为线上版本才算正式上线。

## Important Claims（重要论断）

### 先用 AI 编程返工多，常因没确认理解就动手

一个功能来回改好几轮仍不符合预期，原因之一是还没确认 AI 对需求的理解，就让它开始写代码。先让它出方案、确认理解一致再开发，能减少因理解偏差造成的返工。

### 计划模式：先出方案，再改代码

在 Claude Code 中，计划模式用于先分析项目、给出方案，确认后再开始修改代码；涉及代码细节看不懂时，可以让模型用中文解释清楚。

### 工具分工比单点生成更重要

使用 AI 编程时，除模型能力，工具选择同样重要：Claude Code 负责在项目里生成和修改代码，微信开发者工具负责创建基础项目、运行与手机预览，两者共用同一项目文件夹。

### 真机调试不可省

电脑模拟器上测试没问题，手机上测试可能发现问题，真机调试这一步必不可少。

## Implications（影响／启示）

- 给出 AI 编程个人项目的完整落地路径：小需求起步、同一目录分工、计划模式控返工、真机+备案+审核完成合规发布。
- 需求模板本身是可复用的提示词资产：把范围、排序、状态三态、存储方式与"本次不做"清单一次写清，是减少理解偏差的关键。

## Limitations（局限）

- 单信源教程，操作细节与版本号随工具更新变化，未独立复验。
- 演示项目仅用本地存储、不涉及云开发与账号体系，复杂场景（服务端、多端同步）未覆盖。
