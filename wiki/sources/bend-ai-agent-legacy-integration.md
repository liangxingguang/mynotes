# B端产品经理实操：AI Agent落地旧系统对接的完整框架

## Overview（概览）

公众号「B端产品经理」（作者大皮不皮）第 21 篇。从 B 端产品经理视角给出 AI Agent 对接旧系统的完整落地框架：系统盘点（九字段盘点表）→ 四类对接模式选型 → 字段映射 → 灰度验证 → 复盘总结五步 SOP，并以某连锁零售企业 10 年旧 CRM + 智能工单 Agent 案例给出量化效果（工单录入人力降 40%、T+1→准实时、RPA 写回成功率 95%+）。同专辑已摄入 [[bend-rbac-permission-system-design|RBAC 权限系统设计]] 一篇。

## Key Facts（关键事实）

- **旧系统对接三大坑**：技术方案反复改、灰度范围失控、上线后数据质量不达标；对接是 PM 主导的落地工程，不是纯技术执行。
- **系统盘点九字段**：系统名称与业务域、数据库类型与版本、是否提供 API（REST/SOAP/WebService）、认证方式（Token/OAuth/账户密码）、数据实时性（实时/准实时/T+1）、文档完整度、负责人与审批路径、变更频率与发版窗口、历史故障与性能瓶颈；产出物《旧系统对接盘点表》。
- **四类对接模式**：①API 对接（有标准接口优先，稳定可维护，适合高频读写）；②数据库只读+事件表（无 API 但可申请只读，事件表/时间戳捕获增量，只读降写坏风险）；③RPA/UI 自动化（无 API 无库权限，模拟人工查看/输入/提交，适合低频规则固定写动作，不适合高频实时）；④中间件/消息网关（多系统互调建统一对接层，Agent 只对接网关）。
- **选型五维度打分**：实时性、安全、开发投入、稳定性、可维护性。
- **落地 SOP 五步**：系统盘点 → 方案选型 → 字段映射（数据字典/状态流转/异常码/幂等键）→ 灰度验证（先只读后写、白名单/限流/人工确认开关、少量门店单据起步）→ 复盘总结（对照上线指标决定是否扩量）。
- **案例（某连锁零售用户支持部）**：旧 CRM 建设超 10 年、无标准 API、只有老旧客户端+可只读数据库；Agent 自动识别意图/创建工单/分派门店/夜间批量回写。数据读取用只读账户+事件表捕获增量；写回用 RPA 按固定规则模拟人工+失败重试+人工接管；安全边界为 Agent 不直接写核心表、只写中间表由人工确认后同步。
- **PM 关键动作**：提前 2 周申请数据库只读权限；与业务方制定工单状态流转与分派规则形成数据字典；灰度先 1 家门店跑 2 周（只读+待确认写回）稳定后扩 10 家；每日数据核对看字段准确率与漏单。
- **案例效果**：工单录入人力投入下降约 40%，录入及时性从 T+1 提升到准实时，RPA 写回成功率 95% 以上，剩余失败单人工兜底。
- **六个常见问题**：文档缺失（找供应商补或从表结构/日志反推）、权限申请慢（提前发起先只读）、数据质量差（Agent 入口清洗层+脏数据拦截）、写动作风险（禁直接写核心库，中间表+人工确认）、跨系统一致性（幂等键+重试避免重复写单）、旧系统性能差（限制查询频率、错峰执行批量）。
- **PM 三个核心动作**：把业务目标翻译成系统能力要求；用风险预案替代技术理想主义（降级/人工接管/回滚）；用灰度数据说服业务方（不一上线全量）。

## Important Claims（重要论断）

### Claim 1

旧系统对接是 Agent 落地的首要关卡，PM 不应把它当纯技术执行，而是主导的落地工程。若提前不做系统盘点，典型结果是技术方案反复改、灰度范围失控、上线后数据质量不达标。

### Claim 2

四类对接模式应按系统能力（有无 API、有无库权限、调用频率）选型，而非一刀切；混合模式（如"数据库只读+事件表+RPA 写回"）是常见且可行的组合。

### Claim 3

写动作必须设安全边界：Agent 不直接写核心表，只写中间表由人工确认后同步；配合幂等键与重试机制避免重复写单。

## Implications（影响／启示）

- （解读）B 端 Agent 落地的瓶颈往往不在模型而在旧系统接入：接口/文档/权限三缺，PM 的价值在于把"连接真实数据"变成可盘点、可灰度、可复盘的工程。
- （解读）"先只读、后写、中间表+人工确认"的灰度顺序，与权限模型中"读写分离、变更类强制审批"的思路一致，可组合使用。

## Limitations（局限）

- 公众号实操经验文，案例为匿名口述（"某连锁零售企业"），无公司名与可核验出处；量化效果（40%、95%+）为作者自述，未经独立验证。
- 四类对接模式未覆盖：消息中间件已有资产复用、API 网关改造、数据同步中间件（如 CDC/ETL）等更深的工程选项；选型维度未给打分权重。
- 文末引导"后台回复领取模板"属营销话术，模板本身未随文提供。
