# 淘宝天猫海外技术的AI Native研发范式升级实践与思考

## Overview（概览）

微信公众号文章，记录淘海外技术团队的 AI Native 研发范式升级实践，分两个阶段。第一阶段 **SDD 驱动**：以文档驱动前后端代码生成（规格即指令、代码是规格的产物），六阶段 SOP，AI Coding 占比从 5% 提至 85%，但业务体感不明显——编码时间只占需求全周期约 20%，编码 200% 提效仅带来约 10% 真实提效，瓶颈在「需求→PRD→实现→验收」串行流转。第二阶段 **Agent 驱动**：以钉群为统一工作界面，「AI 执行 + 人决策」，四类 AI 分身自动接力走完澄清→方案→编码→数据全链路，真人只守三个卡点，按需求复杂度分双流程。已在供给/支付/营销三域验证，小需求研发估时降低 50%。团队一手实践，单信源，置信度中。

## Key Facts（关键事实）

- **SDD 阶段成果与体感误差**：文档驱动前后端代码生成，规格即指令、代码是规格产物；六阶段 SOP（项目准备→需求澄清→技术提案→提案执行→测试执行→完结归档）；AI Coding 占比 5%→85%，但编码时间只占需求全周期约 20%，编码 200% 提效仅带来约 10% 真实提效，大量时间花在需求对焦、PRD 编写评审、方案评审、联调测试。
- **范式底层判断**：拉齐业产技工作界面、降低沟通协同时间；ChatBox 是迄今大规模跨人群验证的 AI 产品范式，钉钉是最大的 ChatBox 场景；给钉钉装 Agent 大脑可端到端完成协作与执行。未来排期从「研发资源排队」变为「风险与依赖排队」。
- **核心方案**：把「人驱动」交付链路重构为「AI 执行 + 人决策」——运营在钉群一句话发起，产品/技术PM/研发/分析师四类 AI 分身自动接力走完需求澄清、方案设计、编码交付、数据分析；真人只在三个卡点把关（PRD 人工确认、AI 测试验收、真人终验）。
- **关键路径三要素**：通道（钉群作为唯一工作界面和上下文载体）/ 角色（AI 负责产出、人负责决策）/ 流程（需求→设计→澄清评审 GATE→交付→发布上线 GATE 整链在项目群执行）。
- **按复杂度的双流程**：≤5 人日——编码、测试、验收全部群内完成，AI 直接生成 Diff 与 Test Report；>5 人日——群内聚焦 MRD/PRD/技术方案评审与上下游协同，vibe coding 回本地 IDE 完成后回群更新。
- **自动化交付验证**：PRD 与技术方案合并为机器可执行 Spec，AI 自动跑编码、单测、回归、部署、校验、发布，人只守方案放行、核心 CR、灰度放行三个 GATE；流水线挂客观质量门禁，异常自动回滚；人工卡点按风险分级 L1–L4。
- **实践成果**：供给、支付、营销三域完成真实项目验证；供给域小需求 AI 通过代码分析纠正技术方案，研发估时降低 50%；小需求基本完成 L3 级交付，大部分需求仍停留 L2。
- **目标指标**：小需求（≤5 人日）零研发投入、Agent 端到端当天上线；中大型需求交付周期压缩 20%~30%；月度交付量提升 40%；AI 初稿采纳率 ≥80%；AI Coding 占比小需求 90%→99%~100%、中大型 60%→90%。
- **进一步迭代**：从「AI 分身」（需求级，一需求一群，需求结束群解散）走向「数字员工」（常驻业务域、职责范围与授权边界内主动认领需求，超出边界才升级给人）。

## Important Claims（重要论断）

### 编码提效 ≠ 端到端交付提效

AI 生码率与端到端实际交付效率之间存在巨大鸿沟：个体研发快了，组织交付并没有变快。真正的效率瓶颈隐藏在业产技「需求→PRD→实现→验收」的串行流转中，杠杆点在协同模式转变——串行协同→并行协同，人写人审→AI 生成人决策。

### 衡量口径应从「AI 生码率」转向「端到端交付周期」

跑通后交付吞吐不再线性依赖人力规模，而取决于知识库质量、领域 Skill 覆盖度与权限边界管控的可信度。

## Implications（影响／启示）

**解读**：本信源以真实团队数据印证 [[ai-native-sdlc|AI 原生 SDLC]]「瓶颈转移到编码两侧」与 [[ai-native-organization|AI 原生研发组织]]「协同模式重构」的核心判断——编码 200% 提效仅 10% 端到端提效，是「单点提速≠端到端提速」的又一国内大厂实证；其「AI 执行 + 人决策」「双流程按复杂度分流」「从 AI 分身到数字员工」给出了组织层落地的可操作路径。

## Limitations（局限）

- 团队一手自述，指标（估时降低 50%、交付周期压缩 20%~30%、月度交付量提升 40% 等）为自报口径，未附第三方验证。
- 单信源；L1–L3 分级、双流程的长期效果与风险未展开。
