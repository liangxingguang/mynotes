# AI Coding之后：搜广推团队的研发工程化探索

## Overview（概览）

高德搜索、推荐、广告技术团队 Agent Teams 系列总纲篇。围绕"让 Agent 承担更完整的任务、让人的经验成为团队可复用能力"，把一次真实业务交付拆成**意图、上下文、评审、评估**四个衔接环节，并以四仓协同、双仓改造、真机验证三次实际交付说明各环节如何配合，最后给出团队使用覆盖规模与四维衡量口径。本篇为系列开篇，交付篇、数字员工篇、现场篇在后续推出。

## Key Facts（关键事实）

- **四仓协同**（商铺出租/出售类目建设）：同时涉及业务服务、商品搜索、词典配置、引导推荐 4 个仓库；设计阶段 Agent 先检索代码统一业务语义，各仓并行实现，联调发布遵循依赖顺序。规模：4 个仓库、4 个 CR、1,548 行变更；逐仓设计检查 4/4 通过，冒烟验证 3 通过、1 个因缺环境未执行；需求输入、设计确认和 CR 评审由人工参与。4 个 CR 于 7 月 3 日提交，7 月 14 日完成人工评审、联调和归档。
- **双仓改造**（详情页周边搜索距离筛选）：涉及引导推荐与推荐服务 2 个仓库、2 个 CR、12,480 行变更；统一距离单位、新增能力默认关闭、参数无效时沿用存量行为。首轮冒烟验证失败后 Agent 进入修复循环，一轮修复并复检通过，随后推进两个 CR 归档，代码评审仍由人工完成。
- **真机验证**（96 个业务模块改造）：多 Agent 协同识别模块和批次、定位真实入口、完成代码改造，调度云真机采集截图与结果；四批执行产生 96 份结果文件、795 张过程图。一次阶段检查结果为 9 PASS、47 FAIL、40 BLOCKED，任务仍处于验证和修复过程中。三态对应不同动作：PASS 进入验收、FAIL 继续修复、BLOCKED 先补齐环境或执行条件。
- **四环节分工**（意图/上下文/评审/评估）：意图产出可执行规格、异常分支与待确认事项；上下文产出带来源和适用范围的上下文；评审产出变更说明、验证结果与未验证项；评估产出可比较的任务结果、失败原因与改进项。
- **上下文失败案例**：一次 POI 名称错位问题，需求洞察 Agent 检查坐标、召回和已接入的局部渲染路径未找到原因，人工排查发现症在搜索侧另一段未进入 Agent 检索范围的代码——检索覆盖与结论可信度需一起改进。
- **覆盖规模**（截至 2026 年 8 月，团队自报）：需求洞察与反馈 257 名用户、57 个群、1,500 个案例；复杂工程交付 86 个代码仓库、16 个 MCP、36,000 多次调用；真实环境验证 96 个模块、100 台云真机、18 类机型。
- **四维衡量**：交付效率（需求到验收/上线周期、评审等待、人工投入）、交付质量（验收通过、返工、回归与线上问题）、经验复用（重复澄清、重复错误、人工接续）、综合成本（每个合格交付任务的总成本，含模型、运行资源、重试、评审与返工）。
- **人的职责调整**：业务负责人确认目标与边界，工程负责人判断方案和依赖，质量负责人维护验收与评估标准，知识维护者处理内容更新和失效；可恢复、易检查的操作逐步扩大自动执行范围，关键取舍、高成本动作与线上发布仍由人承担。

## Important Claims（重要论断）

### 代码提速之后，缺口在约束、依赖与验证环境

代码生成提速后，需求里没写清的约束、跨仓依赖和验证环境的缺口，会直接影响任务能否交付。因此工程建设重点不在生成本身，而放在四环节上。

### 意图：把隐含要求写进验收条件

需求若只写"增加入口"，实现会留下大量猜测空间；把业务目标、任务范围、关键约束、验收方式与兼容/降级/异常分支提前写成可检查条件，Agent 才能据此实现、评审者才能据此验收。规格有效性的检验标准：能否减少实现中的反复澄清、提前暴露冲突、支撑验收。

### 上下文：知识要经得起代码核验

知识库适合保存相对稳定的架构、规则与接口约定，任务记忆保留具体经验、纠正与偏好；两类信息都要标明来源、适用范围和更新时间，系统变化后相关结论应重新核验。检索要围绕当前任务选择相关代码、知识和日志并保留关键来源，全部塞入上下文只会增加无关信息、让错误更难追踪。

### 评审：结论要能回到具体变更

一次评审要把需求、实现和验证连起来：原先承诺什么、实际改了什么、哪些已验证、哪些条件未满足。差异摘要、规则检查和验证结果整理可交给 Agent，业务语义、架构取舍、重要风险与线上发布由人判断；结论仍要落到可检查的代码和运行结果上。

### 评估：把"修好这次"和"减少下次出错"分开衡量

比较改进要选验收标准明确的任务组，尽量固定代码快照、模型版本和执行条件，整理经验的任务与检验效果的任务分开；经验被后续任务实际调用、减少重复错误或人工投入，才体现复用价值。

## Implications（影响／启示）

- 给 AI Coding 落地提供了一套可直接套用的交付组织框架：每个环节有明确的关键问题与交付产物，评估环节形成"改进回流系统"的闭环。
- 人机分工给出可操作口径：规格与验收由人定，差异摘要与验证整理可交 Agent，关键取舍与发布由人担责。
- 四维衡量提示团队不要只统计代码生成量，要追踪需求到验收的全周期成本与经验复用效果。

## Limitations（局限）

- 总纲篇：交付篇（星舰 10X、星舰 Cloud Agent）、数字员工篇（凌凌漆）、现场篇（轻舟）的机制细节未在本信源展开。
- 覆盖规模与效率数字为团队自报，文中亦说明"回答团队整体提效多少，还需在相近任务类型和难度下持续比较"。
