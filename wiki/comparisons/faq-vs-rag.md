# FAQ vs RAG（问答对问答 vs 检索增强生成）

## Scope（范围）

对比两种问答形态：**FAQ（问答对问答）**——预设答案库的高效匹配；**RAG（检索增强生成）**——文档切块向量化后由大模型综合生成。含两者组合的**双层知识库**设计。范围限于信源（微信 RAG 系列开篇篇）确立的形态辨析，不涉及具体产品实现。

## Comparison Matrix（对比矩阵）

| 维度 | FAQ（问答对问答） | RAG（检索增强生成） |
|---|---|---|
| 本质 | 预设答案库 | 检索 + 生成结合 |
| 数据结构 | 固定问答对数据库 | 文档切分后向量化存储 |
| 匹配方式 | 关键词或语义匹配 | 向量相似度检索 |
| 回答方式 | 直接返回已有答案 | LLM 综合检索结果生成答案 |
| 依赖 LLM | 可以不依赖，实现简单轻量 | 依赖 LLM 生成 |
| 灵活性 | 限于预设问答对，高效匹配 | 能推理、组合生成新答案 |
| 核心优势 | 高效匹配、轻量、稳定 | 灵活、可覆盖海量非结构化文档 |

## Analysis（分析）

**FAQ 的定位**：系统提前整理好问题与对应答案（通常由人工或规则生成），用户提问时通过关键词匹配或语义向量匹配找出最相似的问答对，直接返回答案。核心在于高效匹配，适合答案可预先审定、提问模式稳定的高频标准问题。

**RAG 的定位**：文档切分成小块、转化为向量存入知识库；用户提问时先向量检索最相关片段，再由 LLM 生成自然语言回答。结合了检索与生成，灵活性更强，能推理、组合生成新答案，适合文档海量、问题长尾且多变的场景。

**两者不是替代关系而是分层互补**（信源 2026-11-23 提出的双层知识库）：

- **第一层：FAQ 知识库（人工标注）**——高质量、小而精，存储领域专家撰写并审核的标准问答对，专门针对频繁发生、具有标准答案的问题，目标是提供"零偏差"答案。
- **第二层：向量知识库（文档语料）**——大规模、广覆盖，包含操作手册、行业规范、领域文档等海量非结构化文档，经文本分割、向量化后存入向量数据库，负责 FAQ 层未覆盖的长尾问题和复杂查询。

## Best Fit（适用场景）

### FAQ is preferable when（以下情况 FAQ 更合适）

- 高频、标准化的问题，答案可由领域专家预先撰写并审核。
- 追求"零偏差"与一致性，不允许模型自由发挥。
- 希望实现简单轻量、不依赖大模型，或作为双层知识库的第一层先兜住高频流量。

### RAG is preferable when（以下情况 RAG 更合适）

- 长尾问题与复杂查询，答案无法预先穷举。
- 语料为海量非结构化文档（操作手册、行业规范、领域文档），且需要动态更新。
- 需要模型基于证据推理、组合出新答案，而非仅返回预设文本。

## Important Caveats（重要提醒）

- 单信源、教程式文章，未附实测数据；"零偏差"是第一层 FAQ 的定位目标，非可验证的量化结论。
- 双层知识库的分工（高频→FAQ、长尾→向量库）为作者方案，实际命中率需结合业务语料评估；FAQ 层与向量层的内容边界（哪些问题进哪层）未给判定规则。
- FAQ 的"语义向量匹配"与 RAG 的"向量检索"在技术实现上可共用 embedding 能力，信源未展开此细节，属推断。
