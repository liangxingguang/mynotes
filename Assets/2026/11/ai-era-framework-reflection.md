# 在AI时代回顾互联网黄金时代技术框架

站在 LLM 重塑编程的节点上，大家都已经习惯了用几十秒去生成一个工程模块、用几句自然语言去vibe一套系统。在"极速生成""许愿黑盒"的狂欢里，我忍不住回头去重新审视上一个被奉为神话的时期——热钱涌动、巨头林立的"互联网黄金时代"。

在进入正文之前，我想先为贯穿本文的两个核心概念下个定义：**什么是真正的框架？什么又是伪框架？**

## **一、 什么是框架？**

真正的框架，是**用最小的心智负担，击穿底层的物理复杂度**。
它们构建了一套清晰、稳定且极度克制的 API，帮开发者从冗长、机械的原生写法中彻底解放出来。

*   比如 **Spring Boot** 终结了让人窒息的 XML 配置地狱；
*   比如 **Koa / Express** 用洋葱模型和中间件重塑了高并发异步 I/O ；
*   比如 **Vue / React** 把前端从脏乱的 DOM 手工操作拉进了声明式渲染的新纪元；
*   比如 **Prisma / MyBatis** 将关系型数据库与内存对象的映射拉平为几行类型友好的调用。

每一个真框架，都用绝对的工程敬畏心去提升生产力。它们的受众极广、普适性极强、经得起跨越十年的生产环境敲打。

## **二、 程序员的傲慢**

说到这，我不得不提到互联网黄金时代最深的一块遮羞布——程序员的**傲慢。**

15年后到 GPT3 问世之前，程序员的傲慢、大厂的傲慢。

在那个热钱泛滥、大厂市值动辄千百亿美金的黄金时代，诞生了一批三十岁上下、年薪百万、手握期权的大厂"技术新贵"。甚至应届生，能基础搭建出个前后端框架，大厂便能开出数十万的起薪邀约。

人类心理学上，有一个极其普遍的认知偏差：**人总是倾向于把时代的红利，误认为是自己个人的卓越。**

当一个程序员坐在落地玻璃窗前，拿着普通工薪族十年都挣不到的薪水时，他的内心开始产生一种难以遏制的精神焦虑和阶级优越感。

## **三、 伪框架伪技术的产生**

一个高薪架构师向总监汇报："这个业务很简单，用最基础的几个接口、三条 SQL，两天就能上线跑通。"
这在黄金时代的大厂是不被允许的。因为如果事情这么简单，**凭什么给你发 150 万年薪？凭什么证明大厂员工比小公司程序员高贵？**

为了证明自己"配得上这份天价薪水"，大厂程序员们必须拒绝一切直白和纯粹。
简单变成了耻辱，复杂成了护身符。

**如果现实世界不复杂，他们就人为地在系统里制造复杂**——把本来一眼能看穿的业务，层层包裹上"领域驱动"、"六边形架构"、"四层解耦"；把三行代码能写完的逻辑，拆碎散落在七八个文件夹里。

**这些冗余的伪框架，本质上是高薪群体给自己打造的"技术神龛"，用来向高层证明：看，我们在解决世界级的难题。**

就像欧洲中世纪的教会，神父坚持只用普通人听不懂的拉丁文念经，因为一旦《圣经》翻译成了人话，普通人就能自己读懂，神职人员的崇高地位和什一税就会瞬间瓦解。

大厂的部分伪架构师们也是如此。他们发明了一整套脱离人类语言的工业黑话与专有框架：从早期的"企业级全家桶"，到后来的"万物皆插件、中台化下沉"。他们热衷于造出像 Egg.js、Umi 、Weex这样的产物，热衷于在内部分享会上大肆宣讲，以及对外的强力炒作。

**伪技术的真正受众从来不是代码，而是人性的虚荣。** 他们需要用这套晦涩的规矩把普通工程师挡在门外，以此维持一种"我是技术布道者，你们是底层搬砖工"的封建式傲慢。

最讽刺的是，这些在 PPT 上吹得神乎其神的伪框架，生命周期往往短得惊人。只要创始者的晋升答辩通过、股票套现或者跳槽，这套复杂的庞然大物就会立刻失去灵魂，在团队里沦为无用的技术遗产。同时，我真的很想说这些KPI封装技术很无趣，真的很无趣。

当年盲目崇拜大厂的中小团队。因为迷信"大厂的高薪员工一定是对的"，把大厂刷 KPI 的伪框架当圣经请进小公司，结果一个小工单系统跑得比蜗牛还慢，同时遇到问题发现早已无人维护，招来的人天天都在研究怎么解耦，公司最后被这套毫无产出的"伪架构"活活拖垮。

我为什么要写这篇文章，就是因为本司采购的某个项目厂商用到了Weex这种伪技术。同时**黄金时代由高薪带来的傲慢，在 AI 时代换了一件马甲，又借尸还魂。**

当年那群靠堆砌概念证明自己牛逼的人，现在摇身一变，成了"AI 时代布道师"。他们依然鄙视接地气的代码，依然不屑于写清晰的人类文档，他们用大模型在半天内生成上百个包、几十万行连自己都没看过的黑盒垃圾，包装成"颠覆性基建"丢出来。**依然是那股不愿沾手泥土、渴望用低成本的幻觉来维持虚荣的傲慢。**

这里我真的很想说 deepseek 的harness DSH。为什么 DSH 会搞出"Cordis 微内核"、"万物皆插件"、"时空可组合性"，150 多个 npm 子包？

**本质上依然是国内技术圈那套"概念先行、宏大叙事、框架自嗨"的 DNA** 。

团队里的人可能在算法和量化上绝顶聪明，但在做系统架构时，依然不可避免地滑向了"我要定义一套宇宙终极范式"的精英傲慢中。他们像当年的大厂架构师一样，陶醉于自己设计的完美星系，却忘了最基础的地面工程——连命令行参数、编码格式和最基础的文档都没走通。代码大段大段AI生成、文档大段大段AI生成。

## **五、 Claude Code 的克制与 DSH 的虚浮**

同样是面向 AI 时代、同样有大模型重度参与开发，只要把 claudecode、codex等和 DSH摆在一起，你就能直观地看到：**什么是敬畏现实的严肃工程，什么是脱离地面的技术自嗨。**

很多人以为 Claude Code 这种工具背后也有什么宏大的理论。但拉开它的源码和架构，它克制得令人发指：

*   它就是一个跑在终端里的纯粹 CLI；
*   它的核心工具集简陋到只有五六个最原始的命令：View、Edit、Bash、Glob、Grep；
*   它没有搞什么"万物皆插件"，没有搞 150 个子包的元宇宙，它的所有代码和精力，都在死磕最底层的 Unix 管道、进程信号量控制、Token 预算的动态剪枝，以及每一次 Git Diff 的原子性修改。

A家的工程师当然也在重度使用 AI 辅助开发，但他们的骨架是由真正懂系统工程、懂终端生态的人死死控住的。

反观 DSH？
它试图用一套原本用来写聊天机器人的微内核理念，去接管复杂的操作系统级 Agent 调度。
上层是炫目的"时空可组合性"，下层却连 Windows 系统的 PowerShell 编码页都处理不好；文档里煞有介事地写着各种高级运行模式，命令行跑起来告诉你参数根本不存在。
**这不是懂系统工程的人在用 AI 提效，这是典型的"黑盒许愿"**——架构师在概念层面提了一个自认为宏大的世界观，然后把具体实现、适配和文档全盘外包给大模型。

## 六、Vibe Coding 不是工业工程的未来

几十年前，软件工程界就试图寻找能一劳永逸解决软件危机的"银弹"。

作为软件工程圣经的《人月神话》， 提出了一个至今依然颠扑不破的本质划分：**软件的复杂度，分为"偶发复杂度（Accidental Complexity）"与"根本复杂度（Essential Complexity）"。**

*   **偶发复杂度**，是指我们在表达逻辑时不得不承受的技术摩擦：记忆繁琐的 API、配置复杂的构建工具、写那些机械重复的胶水代码和样板语法。
*   **根本复杂度**，则是业务实体之间的关系推演、状态机的边界、并发竞争条件、异常回退策略，以及数据流动的逻辑自洽。

大模型是一柄极其强悍的杠杆，**它真正能粉碎的，是庞大的"偶发复杂度"。**
不管是 Java 冗长古板的 Bean 映射，还是手写增删改查的重复劳动，AI 都能在几秒钟内替你铺平。在现代工程工具辅助下，一个全栈工程师能获得前所未有的数倍生产力。

**但无论模型演进到哪一代，它都无法替人类抹平系统内生性的"根本复杂度"。**

在 AI 时代，成熟工程师的姿态往往不是极端的放任，也不是守旧的排斥，而是一种更平稳的平衡：

1.   **把规格（Spec）和类型当成锚点**：
正因为代码生成变得极快，严谨的接口文档、TypeScript 的结构化类型，以及关键路径的单元测试，才变成了系统唯一的"防腐层"。我们用高密度的约束来框定边界，让 AI 在安全的安全网内快速发挥。
2.   **工程师的精力向"根本问题"收敛**：
不再需要为记忆繁琐的框架语法消耗认知负荷，工程师终于可以把宝贵的大脑带宽，集中在真正重要的设计上：模块与模块之间的权责划分、关键链路的数据一致性、以及系统在极端异常下的优雅降级。
3.   **保持对每一处变更的知情权**：
在终端或 IDE 里认真审阅每一次 Git Diff，不是因为不信任技术，而是因为在这个充斥着黑盒的时代，**对系统运行状态保持诚实与清醒，是专业开发者最底层的操守。**

AI并没有改写软件工程的客观物理规律，它只是把我们从杂务中解放了出来，逼着我们直面软件工程本质问题：剥离掉所有的语法噪音和框架仪式感之后，是否真的具备理清系统本质复杂度的能力？
