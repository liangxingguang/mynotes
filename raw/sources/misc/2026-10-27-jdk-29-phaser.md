# Phaser——比CyclicBarrier更灵活的同步屏障

> 读完本文你将理解：为什么说 Phaser 是 CountDownLatch 和 CyclicBarrier 的"完全体"，以及它如何用位运算把一个 int 变量玩出花。

* * *

## 一、Phaser 是什么？

**Phaser**（发音：/ˈfeɪzər/，"移相器"）是 JDK 7 引入的同步工具，放在 `java.util.concurrent` 包下。它本质上是一个**可重用的、支持动态注册参与方的同步屏障**。

如果你用过 CountDownLatch 或 CyclicBarrier，可以这样理解：

*   **CountDownLatch** 是一次性的，参与方数量固定，倒数到 0 就结束
    
*   **CyclicBarrier** 可以重用，但参与方数量还是固定的，所有人到齐才一起走
    
*   **Phaser** 是它们的超级增强版：**可以重用 + 参与方可以动态增减 + 支持分层 + 可分阶段 + 有终止状态**
    

用一句话概括：**Phaser 是灵活版的 CountDownLatch + 增强版的 CyclicBarrier**。

### 继承体系

```
java.lang.Object  └── java.util.concurrent.Phaser
```

Phaser 没有实现任何接口，就是一个独立的工具类。但它内部的设计非常精妙——用**一个 `volatile long` 变量**就编码了所有状态信息。

### 核心概念

概念

说明

**party（参与方）**

注册到 Phaser 上的线程/任务，可以用 `register()` 动态添加

**phase（阶段）**

从 0 开始的递增编号，所有 party 到达后自动 +1

**arrive（到达）**

一个 party 完成当前阶段的工作，到达屏障

**advance（推进）**

最后一个 party 到达后，阶段自动推进到下一阶段

**termination（终止）**

Phaser 进入终止状态，所有等待方法立即返回

## 二、核心源码剖析：一个 state 变量玩出花

Phaser 最让我佩服的设计，是它用**一个 64 位的 `volatile long` 变量 `state`** 存储了全部状态信息，通过位运算来读取/修改：

```
// Phaser 源码中的核心状态变量（简化理解版）// 实际声明：private volatile long state;/** * state 字段的 64 位布局： *  * ┌─────────┬──────────┬──────────┬──────────────┐ * │ unarrived (16 bits)  │  phase (32 bits) │ arrived (16 bits)  │ * └─────────┴──────────┴──────────┴──────────────┘ *  bit 63-48   bit 47-32   bit 31-16    bit 15-0 *  * 注意：JDK 不同版本的位分布略有差异，JDK 17+ 优化了布局 * 核心思想不变：unarrived（未到达）+ phase（阶段）+ arrived（已到达） */
```

这个设计的巧妙之处在于——**整个状态更新可以通过一次 CAS 操作完成**，不需要多个字段 + 多重锁。来看几个关键的位操作：

```
// 核心常量（JDK 17+ 版本，摘自源码逻辑）private static final int  PARTIES_SHIFT   = 16;  // parties 字段偏移private static final int  PHASE_SHIFT     = 32;  // phase 字段偏移private static final int  UNARRIVED_MASK  = 0xffff;  // 低 16 位private static final long PARTIES_MASK    = 0xffff0000L;  // 中间 16 位private static final long COUNTS_MASK     = 0xffffffffL;  // 低 32 位private static final long TERMINATION_BIT = 1L << 63;      // 最高位←终止位private static final int  MAX_PARTIES     = 0xffff;  // 65535// 从 state 中提取 parties（已注册的参与方总数）private int partiesOf(long s) {    return (int)(s >>> PARTIES_SHIFT);}// 从 state 中提取 arrived（已到达的参与方数）private int arrivedOf(long s) {    int counts = (int)s;    return (counts >>> 16) - (counts >>> 16);      // 实际上是 parties - unarrived，等价于已到达数}// 从 state 中提取 unarrived（尚未到达的参与方数）private int unarrivedOf(long s) {    int counts = (int)s;    return counts & UNARRIVED_MASK;}// 从 state 中提取 phase（当前阶段编号）int phaseOf(long s) {    return (int)(s >>> PHASE_SHIFT);}
```

### arriveAndAwaitAdvance() —— 最常用的方法

这是 Phaser 使用频率最高的方法，等价于 `CyclicBarrier.await()`：

```
/** * 到达屏障，等待其他参与方，所有方到齐后一起进入下一阶段。 *  * 核心流程： * 1. CAS 将 state 中的 unarrived 减 1 * 2. 如果减完后 unarrived != 0，说明不是最后一个到达的 → 自旋等待 * 3. 如果减完后 unarrived == 0，说明是最后一个到达的 → 触发阶段推进 */public int arriveAndAwaitAdvance() {    // 简化版核心逻辑（实际源码涉及树形结构和终止状态处理，更复杂）    // 1. 自旋 + CAS 减少 unarrived    for (;;) {        long s = state;        int phase = (int)(s >>> 32);       // 当前阶段号                // 检查是否已终止        if (phase < 0)            return phase;                int unarrived = (int)s & 0xffff;   // 当前未到达数                if (unarrived <= 0)            throw new IllegalStateException("已经没有未到达的 party 了！");        // 2. CAS 更新：unarrived - 1        // 构造新 state：保持高 32 位(phase+parties)不变，低 16 位(unarrived) -1        if (UNSAFE.compareAndSwapLong(this, stateOffset, s, s -= 1)) {                        // 3. 判断：我是最后一个到达的吗？            if (unarrived > 1) {                // 不是最后一个 → 自旋等待阶段推进                 //（ForkJoinPool 的管理线程如果等待会继续执行其他任务，普通线程自旋）                return internalAwaitAdvance(phase, null);            }                        // 4. 我是最后一个到达的！触发阶段推进            if (parent != null) {                // 如果有父 Phaser，先把到达通知给父                parent.doArrive(...);            }                        // 5. 计算新的 state：phase + 1，unarrived 重置为 parties            long n = s & 0xffffffff00000000L; // 清空低 32 位            n |= (s & 0xffff0000L) >>> 16;    // parties 复制到 unarrived 位            n += 1L << 32;                      // phase + 1            // 6. CAS 更新 state 到下一阶段            UNSAFE.compareAndSwapLong(this, stateOffset, s, n);                        // 7. 调用 onAdvance() 钩子（子类可覆写）            if (!onAdvance(phase, partiesOf(s)))                return phase; // 阶段推进成功                        // 8. onAdvance 返回 true → 进入终止状态            // ... 设置终止位，唤醒所有等待线程            return phase;        }    }}
```

**关键设计细节**：

1.  **全程无锁**：只用 CAS 自旋，没有 synchronized 也没有 ReentrantLock
    
2.  **原子性**：所有状态（phase + parties + unarrived）编码在一个 long 里，一次 CAS 保证一致性
    
3.  **终止位复用**：用 state 的最高位存储终止标记，不需要额外字段

## 三、分层设计（Tiering）

当参与方非常多时（比如几万个线程），所有方都在同一个 Phaser 上自旋等待会带来严重的**缓存一致性开销**（False Sharing + CAS 竞争）。Phaser 的解决方案是**树形分层**：

```
            Root Phaser (phase=3)            /          \      Child P1        Child P2    (phase=2)       (phase=2)    /    |    \      /    |    \   线程 线程 线程   线程 线程 线程
```

**工作原理**：

*   每个子 Phaser 独立管理自己的一组线程
    
*   只有当子 Phaser 的所有 party 到达后，它才以**单个 party 的身份**向父 Phaser 报告到达
    
*   父 Phaser 的 phase 只在所有子 Phaser 都到达后才会推进
    
*   这样就把**集中式竞争分散到各个子节点**，大幅提升吞吐量
    

```
// 创建分层 Phaser 的示例代码void build(Thread[] tasks, int lo, int hi, Phaser ph) {    int TASKS_PER_PHASER = 4;  // 每 4 个线程共用一个子 Phaser    if (hi - lo > TASKS_PER_PHASER) {        for (int i = lo; i < hi; i += TASKS_PER_PHASER) {            int j = Math.min(i + TASKS_PER_PHASER, hi);            build(tasks, i, j, new Phaser(ph)); // 递归创建子 Phaser        }    } else {        for (int i = lo; i < hi; ++i)            tasks[i] = new Thread(() -> {                // 每个线程在构造时自动 register 到自己的子 Phaser            });    }}
```

## 五、使用示例

### 示例1：分阶段任务（3个阶段，各阶段不同逻辑）

```
import java.util.concurrent.Phaser;/** * 模拟一个考试流程：3 个考生，经历 3 个阶段 *   阶段0：笔试（所有人一起开始） *   阶段1：机试（笔试通过后一起进入） *   阶段2：面试（机试通过后一起进入） */public class ExamPhaserDemo {    public static void main(String[] args) {        // 创建一个 Phaser，主线程占一个名额（用来控制启动）        Phaser phaser = new Phaser(1) {            @Override            protected boolean onAdvance(int phase, int registeredParties) {                // 每个阶段结束时触发                System.out.printf("=== 阶段 %d 结束，参与方: %d ===%n",                     phase, registeredParties);                // 超过阶段 2 就终止                return phase >= 2 || registeredParties == 0;            }        };        // 3 个考生，每人一个线程        for (int i = 1; i <= 3; i++) {            final String name = "考生" + i;            phaser.register();  // 动态注册            new Thread(() -> {                // 重复执行直到 Phaser 终止                while (!phaser.isTerminated()) {                    int currentPhase = phaser.getPhase();                    switch (currentPhase) {                        case 0: System.out.println(name + " 正在答题..."); break;                        case 1: System.out.println(name + " 正在上机操作..."); break;                        case 2: System.out.println(name + " 正在面试..."); break;                    }                    // 完成当前阶段，等待其他人                    phaser.arriveAndAwaitAdvance();                }                System.out.println(name + " 考试结束！");            }).start();        }        // 主线程释放自己的名额，让 3 个考生开始        System.out.println("📢 考试开始！");        phaser.arriveAndDeregister();        // 等待所有考生完成        // 注意：此时主线程已经不注册了，无法用 arriveAndAwaitAdvance        // 因为主线程不是 party 了，直接 sleep 等待        try { Thread.sleep(3000); } catch (InterruptedException e) {}        System.out.println("🏁 全部考试结束！");    }}
```

**运行输出**：

```
📢 考试开始！考生1 正在答题...考生2 正在答题...考生3 正在答题...=== 阶段 0 结束，参与方: 3 ===考生3 正在上机操作...考生2 正在上机操作...考生1 正在上机操作...=== 阶段 1 结束，参与方: 3 ===考生1 正在面试...考生3 正在面试...考生2 正在面试...=== 阶段 2 结束，参与方: 3 ===考生1 考试结束！考生3 考试结束！考生2 考试结束！🏁 全部考试结束！
```

### 示例2：动态增减参与方

```
import java.util.concurrent.Phaser;/** * 分批任务：先 2 个线程一起完成准备阶段， * 中途加入 2 个新线程，4 人一起完成主阶段 */public class DynamicPhaserDemo {    public static void main(String[] args) {        Phaser phaser = new Phaser(1);  // 主线程占 1 个名额        // 第一批：2 个线程        for (int i = 1; i <= 2; i++) {            final String name = "线程" + i;            phaser.register();            new Thread(() -> {                System.out.println(name + " 完成准备工作");                phaser.arriveAndAwaitAdvance(); // 阶段 0                System.out.println(name + " 进入主阶段");                phaser.arriveAndAwaitAdvance(); // 阶段 1                System.out.println(name + " 完成！");            }).start();        }        // 让第一批先开始        phaser.arriveAndDeregister();        try { Thread.sleep(500); } catch (InterruptedException e) {}        // 中途加入第二批：2 个新线程        for (int i = 3; i <= 4; i++) {            final String name = "线程" + i;            phaser.register();            new Thread(() -> {                System.out.println("💥 " + name + " 中途加入！");                System.out.println(name + " 进入主阶段");                phaser.arriveAndAwaitAdvance(); // 阶段 1                System.out.println(name + " 完成！");            }).start();        }        System.out.println("📊 当前参与方总数: " + phaser.getRegisteredParties());    }}
```

## 六、注意事项和踩坑指南

### 1\. 最大 65535 个 party

```
// ❌ 这会抛出 IllegalStateExceptionPhaser p = new Phaser(65536);  
```

如果你需要超过 65535 个 party，必须用**分层 Phaser**。

### 2\. deregister 可能导致自动终止

```
Phaser phaser = new Phaser(3);// ... 3 个线程各自 arriveAndDeregister// ⚠️ 当最后一个线程 deregister 后，registeredParties == 0// 默认的 onAdvance() 检测到 parties==0 返回 true → 终止！
```

`onAdvance(int phase, int registeredParties)` 的**默认实现是 `return registeredParties == 0;`**，所以当所有方都注销后，Phaser 自动终止。如果你不希望这个行为，可以覆写 `onAdvance`。

### 3\. arriveAndAwaitAdvance 不可中断

```
// ⚠️ 这个方法不响应中断！即使线程被 interrupt() 也会继续等int phase = phaser.arriveAndAwaitAdvance();// 如果需要可中断的版本，分两步：phaser.arrive();phaser.awaitAdvanceInterruptibly(phase);  // 这个可以响应中断
```

### 4\. 性能：分层 vs 不分层

场景

< 8 个线程

✅ 最好的选择

8-64 个线程

64-1000+ 个线程

✅ 显著提升吞吐量

### 5\. 和 ForkJoinPool 的协作

Phaser 内部对 ForkJoinPool 有特殊优化——当等待线程是 ForkJoinPool 的 worker 时，它不会纯自旋，而是会去**执行其他排队的任务**，避免浪费 CPU。这个设计非常精细。

### 6\. 不要忘了 register 和 deregister

```
// 常见错误：忘了 register 就直接用Phaser phaser = new Phaser(0);  // 0 个 party！Thread t = new Thread(() -> {    phaser.arriveAndAwaitAdvance();  // 💥 IllegalStateException!});// 正确做法：phaser.register();  // 先注册// 或者构造时指定 Phaser(1)
```

### 什么时候用哪个？

```
场景：等一批任务全部完成 → 只需要通知一次选：CountDownLatch ✅（最简单，不需要重用）场景：N 个线程周期性同步，N 固定不变选：CyclicBarrier ✅（语义清晰，barrierAction 方便）场景：线程要一起经历多个阶段，或者需要动态增减参与方选：Phaser ✅（唯一选择）场景：超大规模并发同步（> 64000 个线程）选：Phaser（分层模式）✅（唯一选择）
```

## 八、写在最后

说实话，在我开始认真读 Phaser 源码之前，我以为它只是一个"升级版 CyclicBarrier"。真正读进去之后才发现，它用位运算实现状态编码的简洁性、分层的扩展性、与 ForkJoinPool 的深度集成——这些设计都远超一个"加强版屏障"的定位。

我觉得 Phaser 最值得学习的设计理念是：**把状态编码进一个变量，用 CAS 统一操作**。这种"无锁"思路在 JUC 中反复出现（AtomicInteger、LongAdder、AQS...），而 Phaser 把它发挥到了极致——所有状态都在一个 long 里，一次 CAS 就能原子地完成"到达检查 + 阶段推进"。
