## 分段与 MSS

由于 IP 层和 MAC 层对数据包长度有严格限制，TCP 把数据交给 IP 层之前，必须先将过大的数据拆成多个大小合适的段（Segment），确保每个段长度在允许范围内。

示例：客户端 HTTP 层准备发送 18 字节字节流，前 15 字节先到达 TCP 层，被打包成段并加 TCP 头部，再在 IP 层加 IP 头部，经网络到达服务器。若 TCP 段超过 IP 层最大长度，IP 层会再做分片（fragmentation），非常消耗资源，应尽量避免。

**MSS（Maximum Segment Size，最大报文段长度）** 的选取目标：

- 每次传输尽可能多的数据，提升效率；
- TCP/IP 头部占比尽量小，降低开销；
- 避免 IP 层再次分片。

现代网络中 MSS = 1460 字节：

- 以太网 MTU = 1500 字节；
- IP 头部 20 字节，TCP 头部 20 字节；
- MSS = 1500 − 20 − 20 = 1460（纯数据部分，不含头部）。

MSS 在三次握手时协商，位于 TCP 首部选项字段：

- 客户端在 SYN 中声明自己建议的 MSS（如 1460），称发送方 SMSS；
- 服务器在 SYN-ACK 中声明自己的 MSS（如 1400），称接收方 RMSS。

## TCP 重传

可靠传输的两个关键机制：

- **确认应答（ACK）**：接收方成功收到数据后回复确认；
- **重传机制**：发送方在规定时间内没收到 ACK，即认为数据可能丢失，重新发送。

基础模型：发数据 → 启定时器 → 超时前收到 ACK 则重置定时器继续；超时未收到则重传。缺点是停等，效率低。

优化：给每条消息分配编号（即 TCP 序列号），可连续发送多条消息，每条各自关联定时器与 ACK；某条丢失只需重传那一条。

序列号示例：某段长 647 字节，此前已发 1461 字节，则下一段从第 2108 字节（1461+647）开始。序列号是 32 位无符号整数，0 ~ 2³²−1，超出后回绕到 0。

**序列号回绕的歧义问题**：假设序号最大到 4，#2 丢失后延迟到达；发送方发完 #4 回绕经 #0、#1 时，旧 #2 的重传到达，接收方无法区分它是旧数据还是新一轮的第 2 字节。

解决：TCP 选项引入**时间戳（timestamp）**。接收方把收到段的时间戳 B 与上一个正常收到包的时间戳 E 比较：B ≤ E 即重传的旧数据，否则是新数据（PAWS 思路）。同序号段也能据此判断新旧。

## TCP 快速重传（Fast Retransmit）

无需等待定时器超时即可尽早发现丢包：

- **规则 1（接收方）**：每收到一个段，都在 ACK 确认号中回复"期望收到的下一个序列号"。收到 #1 回 ACK 2；之后收到 #3、#4 而 #2 未到时，反复回复 ACK 2。
- **规则 2（发送方）**：连续收到 3 个重复 ACK，即判定该段丢失，立即重传，不等超时。

示例：#3 丢失，接收方收到 #4、#5、#6 时各回一次 ACK 3；发送方收到三个重复 ACK 3 后立即重传 #3；补齐后接收方回 ACK 7。

遗留问题：快速重传前发送方不确定 #5、#6 是否已被接收；若它们也丢了，仍要等超时。由此引入 SACK。

## TCP 选择性确认（SACK）

SACK（Selective Acknowledgment）通过 TCP 选项字段实现：接收方在 ACK 中额外告知哪些非连续区间已成功收到（例如 SACK 指出 2872~3393 已收到）。发送方据此精确知道哪些段不用重传、哪些可能丢失，进行有针对性的重传，避免重复发送和无谓等待。

## 总结

- **MSS** 决定 TCP 报文段长度上限（以太网下 1460，握手时协商 SMSS/RMSS）；
- **定时器超时重传**是可靠传输的基础手段；
- **快速重传**在连续 3 个重复 ACK 时不等超时立即重传，加快丢包恢复；
- **SACK** 让接收方告知非连续已收区间，发送方只重传真正丢失的部分。
