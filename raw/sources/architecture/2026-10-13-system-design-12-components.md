# 一次讲清 12 个系统设计核心组件

系统设计是软件开发过程中至关重要的一环，它不仅决定了系统的整体架构，还涉及各个组件之间如何协作与集成，最终影响系统的可扩展性、可靠性和运行效率。本文从实际开发中最常见的场景出发，介绍每位开发人员和架构师都应熟悉的 12 个系统设计核心要素（各组件均为概念性介绍，原文配有架构示意图与视频讲解）：

- **分布式消息队列**：系统各组件间传递消息的中间层。生产者发消息到队列，消费者从中取消息处理，组件间不必直接通信，降低耦合、便于扩展。
- **DNS（域名系统）**：将域名（如 www.example.com）解析为对应 IP 地址，浏览器据此把请求发送到正确的服务器。
- **负载均衡器**：高并发时把请求分配到多台服务器，避免单机过载；部分服务器故障时可把请求转发到可用节点，提升可靠性。
- **分布式缓存**：把频繁访问的热点数据放在内存中，减少数据库查询，缩短响应时间并支撑更高并发。
- **数据库**：数据存储与管理的核心。关系型数据库以预定义表的行列存储；文档型数据库以类 JSON 文档存储，结构更灵活，应按需求选型。
- **分布式任务调度器**：管理按预定时间执行的任务（每日报表、定期清理、定时同步），负责任务编排、多机分配与故障恢复。
- **可观测性**：收集分析指标、日志与链路追踪数据，了解系统状态、发现性能瓶颈、追踪请求在各组件间的流转，快速定位问题。
- **非结构化数据存储**：图片、视频、文档等无法用关系表组织的数据，采用 BLOB 等专门存储方案，支持按需扩展，灵活经济。
- **扩展服务**：垂直扩展即提升单机硬件性能；水平扩展即增加服务器数量分摊负载，合理选型以在高负载下保持响应速度与可靠性。
- **发布-订阅模型（Pub-Sub）**：发布者把消息发到主题，订阅者订阅感兴趣的主题即可接收，无需知道对方身份，实现异步解耦。
- **唯一 ID 生成器**：多台服务器独立生成 ID 易重复冲突，分布式系统需要可靠的全局唯一标识机制来区分和关联订单、用户、任务等实体。
- **限流**：限制客户端在一定时间内的请求数量，防止突发流量或恶意滥用挤占资源，保障其他用户正常访问。
