## 一、先看全景：JVM运行时数据区

当你在命令行敲下 java HelloWorld 时，JVM启动并划分出下面这些内存区域：

记住一个核心划分：**线程私有 vs 线程共享**。线程私有的三个区域，每个线程都有一份；线程共享的区域，所有线程一起用。

**面试官最爱问：**"JVM运行时数据区包含哪些？" 标准回答：程序计数器、虚拟机栈、本地方法栈（线程私有）+ 堆、元空间（线程共享）。JDK8把方法区从永久代改成了元空间，这又是一个追问点。

## 二、程序计数器（PC Register）—— 最简单但也最重要

程序计数器就是一块很小的内存，记录**当前线程正在执行的字节码行号**。你可以把它理解为代码的"书签"——CPU执行到哪一行了，全靠它记录。

### 核心特征

*   **唯一不会OOM的区域：**

    JVM规范里明确说了，程序计数器不会抛出OutOfMemoryError

*   **线程私有：**

    每个线程有自己的PC，CPU切换线程时靠它恢复执行位置

*   **执行native方法时为undefined：**

    因为native方法不是Java字节码，不需要记录行号

```

```

**常见原因：**1\. 递归没有正确终止条件 2. 方法调用链太深（几千层）。解决方案：改成循环，或增大栈空间 \-Xss 参数。

## 四、堆（Heap）—— Java世界的"房地产"

堆是JVM管理的**最大一块内存**，所有**通过new创建的对象和数组**都存在堆里。它也是GC（垃圾回收）的主要战场。

### 堆的分代结构（JDK8经典模型）

对象的"生命旅程"：

1.  **出生：**

    new出来的对象先放进Eden区

2.  **第一次GC（Minor GC）：**

    活下来的对象复制到S0区，年龄+1

3.  **多次GC：**

    在S0和S1之间来回复制，每次年龄+1

4.  **晋升：**

    年龄超过阈值（默认15），从新生代搬到老年代

5.  **大对象：**

    特别大的对象直接进老年代，不走新生代

### OutOfMemoryError: Java heap space —— 堆炸了

**典型场景：**while循环里不断new对象且被引用持有、一次性加载大量数据到内存、集合类忘记清理。排查思路：加 \-XX:+HeapDumpOnOutOfMemoryError 导出dump文件，用MAT/JProfiler分析。

## 五、元空间（Metaspace）—— 类的"档案室"

JDK8之前叫"永久代"（PermGen），存在堆里，经常OOM。JDK8后移到**本地内存**（直接内存），改名元空间。

对比项

永久代（JDK7及以前）

元空间（JDK8+）

存放位置

堆内存（JVM管理）

本地内存（操作系统管理）

默认上限

很小，容易OOM

无上限（受物理内存限制）

GC

Full GC时回收

类卸载时回收

调优参数

\-XX:PermSize / -XX:MaxPermSize

\-XX:MetaspaceSize / -XX:MaxMetaspaceSize

**什么时候元空间会OOM？**动态生成大量类（如CGLIB代理、JSP编译、Lambda表达式），每个类都要在元空间占位置。如果遇到 OutOfMemoryError: Metaspace，说明你动态生成了太多的类。

### 标准答案（加分的逐条分析）

1.  **① int i = 10：**

    基本类型的局部变量，直接存**虚拟机栈**（main方法栈帧的局部变量表），不经过堆

2.  **② String s = "hello"：**

    字符串常量"hello"存在**堆中的字符串常量池**（JDK7后从方法区搬来的），s这个引用变量本身存在虚拟机栈

3.  **③ Person p = new Person(...)：**

    Person对象实例存在**堆**里，p这个引用变量存在虚拟机栈。Person类本身的元数据（类定义信息）存在**元空间**


**加分回答：**如果能再补一句"JDK7之后字符串常量池从永久代移到了堆中，JDK8之后方法区从永久代变成了元空间"，面试官会觉得你不仅知道现在是什么样的，还知道演变过程——这才是架构师思维。
