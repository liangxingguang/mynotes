01 RAG检索增强生成

Langchain用来做Rag，在实际生产当中几乎不用，因为Langchain的实现没有那么好，它更多是一些基本功能，下面做一个简单演示，你们公司有用这个框架来实现Rag吗，评论区可以分享下。

简单介绍下Rag

如果用户询问公司内部规章制度，大模型通常无法仅凭训练数据回答，因为这些资料属于公司的私有数据。最直接的方法是把制度全文和问题一起输入模型，但会遇到两个问题：

1.  文档可能超过模型的上下文长度；

2.  即使能够放入，信息过多也会使模型难以准确找到与问题有关的部分。

RAG的思路是先把文档切成多个chunk。用户提问时，不把全文交给模型，而是检索最相关的若干chunk，再把这些片段与问题拼接起来，让模型依据片段回答。

RAG中“检索增强”含义是：模型回答前，先从外部数据中找到补充材料，以这些材料增强本次输入。它不会把公司制度永久写入模型参数，也不是再次训练模型。下一次问题仍然需要重新检索。

检索和生成承担不同职责：

阶段

解决的问题

文档切分

长文档变成可检索的基本单元

Embedding

把文本语义表示为可计算的向量

向量索引

保存向量并快速查找相似内容

Top-K召回

本次问题选择哪些候选片段

Prompt拼接

把候选片段和问题交给模型

大模型生成

根据上下文组织自然语言答案

任何一阶段出错都会影响最终结果。检索没有找到正确片段时，即使模型很强，也缺少回答私有问题的依据；检索正确但Prompt没有传入context，模型同样看不到资料。

离线部分负责读取文档、切分、生成向量并建立索引，通常预先完成。在线部分在用户提问后实时检索和生成回答。

### 文本切分与重叠

如果只按固定字数切分，一个完整知识点可能恰好被分到两个chunk 中，导致任何一个片段都不能完整回答问题。

因此，相邻chunk通常保留一定重叠。例如：

```
chunk 1：1 - 200chunk 2：181 - 380chunk 3：361 - 560
```

每两个相邻块有20个字符的交集，可以降低知识点在边界处被截断的风险。重叠不是越大越好：重叠太大会产生更多重复内容。实际值应结合文档和检索效果调整。

例如知识点“员工入职满一年后可享受五天年假”刚好跨越边界：第一个块只有“员工入职满一年后”，第二个块只有“可享受五天年假”。如果用户询问年假条件，两个片段单独看都不完整。让第二块向前重叠一部分，有机会使完整条件出现在至少一个chunk中。

但overlap只是在边界附近复制文本，并不能保证所有知识点都完整。如果一个知识点本身很长，或者分隔符选择不合理，仍可能被拆开。因此，重叠是降低风险的办法，不能绝对保证。

### Embedding与余弦相似度

简单字符串匹配依赖共同词语。两句话即使含义相近，也可能因为用词不同而无法匹配。向量检索先通过Embedding模型把文本转换为固定维度向量，再比较向量相似度。

文档向量和问题向量必须由同一个Embedding模型生成。不同模型的向量即使维度相同，其空间含义也不同，不能直接比较。

可以把Embedding模型理解为同一套“语义坐标系”。文档在离线阶段被放入这套坐标系，用户问题在在线阶段也要放入同一坐标系。随后才能判断哪些文档向量离问题向量更近。

向量不是把每个字简单变成一个数字，也不能从某一维直接读出完整语义。它是模型根据整段输入生成的数值表示。

向量夹角余弦相似度表示语义相似度：

```
cos(θ) = (A·B) / (||A|| × ||B||)
```

分母用于对向量长度进行归一化，夹角越小，余弦相似度越接近1；夹角为180度时为-1。

02 Faiss基本思想

如果有十万个chunk，每个问题都与全部向量逐一比较，计算量会比较大。把大量点组织成若干候选区域，新点到来后优先在可能相关的区域及其附近搜索，从而排除大量不相关点。

Faiss用于向量相似度搜索。向量索引可以用一定的组织结构加快检索，不必每次都从头比较所有数据。

检索速度和检索完整性之间可能存在取舍。只检查少量候选区域会更快，但可能错过边界附近的近邻；因此可以同时考虑相邻区域。“先缩小候选范围，再在候选中比较”这个思想。Faiss是向量相似度搜索与聚类库，LangChain把它作为本地向量存储使用。

不同向量数据库的差异在于怎么去画区域，这是不同向量数据库最大的差异，但基本原理都一样。

Bert模型叫向量模型，BGE、BME全是Bert改良版本，Bert模型直接产生向量，Bert模型叫embedding模型，这是向量检索的基本原理，但Langchain实现rag是比较简单的。

模型文本长度和向量长度没有关系，向量长度只跟模型有关，每个模型都输出固定向量维度，如果两个向量之间要比较相似度，必须是同一个模型产生的向量，不同模型产生的向量没有任何可比性，甚至连长度都可能不一致。

Rag检索增强**原理****，**就是切文档，向量召回，通过大模型得到答案等。

### 03 RAG代码流程

在线部分，数据库读出来进行load，检索器retriever从数据库里检索，按相关性排序取前两个最高的，再构建一个问题模板，用户query直接填用户问题{question}，{context}填写检索信息，制定提示词参数，把prompt\_template塞进来。构建一个链，有大模型，用Langchain的Rag把检索内容和上下文一起组成参数。

比如：“介绍下卓不凡”，输出：“卓不凡是一位武功高强的角色，他能够轻易的从石洞中拿出长剑...”，模型回答的，召回来的。

离线是事先准备好的，写数据库进行查询，写库的过程就是离线的过程，查询是在线，离线一次处理。在线的部分是实时响应用户需求，实时动态跟用户进行交流。

最终进入模型的核心内容仍是：回答要求、检索到的上下文和用户问题。RAG没有改变大模型本身，而是在调用模型之前增加了检索步骤。

### 05 Langchain总结

具体函数可以查文档或借助工具生成，但必须理解运行机制。核心脉络可以归纳为：

真正掌握的是：

*   文本如何经过模板和分词器进入模型；

*   Message为什么要区分system、user、assistant和tool；

*   为什么自由文本需要结构化解析后才能进入传统工作流；

*   工具调用中，模型只负责规划，程序才负责执行；

*   Chain如何把前一步输出传递给后一步；

*   RAG为什么要切分、重叠、向量化和检索；

*   模型具有随机性，工具规划和表达方式可能随运行发生变化。

学习人工智能应用开发时，应主动追问每段代码背后的逻辑，而不是被动记忆写法。理解输入、输出、状态传递和依赖关系后，即使框架接口变化，也能较快定位对应的新写法。
