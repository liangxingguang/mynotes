# 从 0 到 1 拆解 Claude Skills

SKILLS 专栏 01

一次构建，永久生效。把你的判断、偏好、标准、底线，压进一个 .md 文件。以后每一句需求，都不必再解释前言。

1. **Skill 就是一个 Markdown 文件。**不装插件，不写代码。里面装着 Claude 干这类活必须知道的一切：你是谁、写给谁、什么算合格、什么绝不许出现。
2. 同一段背景，你解释到第三遍，它就该变成一个 Skill。**建一次，以后一个字都不用再提。**
3. 建，谁都会。**难的是好用。**同一套流程，有人做出资产，有人做出废纸——分水岭就在下面 7 个动作。

## 01 什么是 Claude Skills

先说人话：**Skills 就是把你脑子里的规矩，写成一个文件，交给 Claude 长期保管。**

技术上，它是**模块化技能包**——一个文件夹，装着指令、脚本、资源，用到才加载。领域知识与工作流就这样被固化下来，**创建一次，长期有效**，不必再重复贴提示词。它能互相组合，也能写代码去做复杂任务。高效、可组合、好搬走。

一句话：把你的经验，变成 Claude 随时能调用的文件。不是提示词。是资产。

传进 Claude 账户，之后每次一句话就能唤醒：

> 「用我的品牌音调 Skill，写一篇关于产品发布的 LinkedIn 帖子。」

Claude 自动调出文件里的全部上下文。产出的结果，就像你刚刚把背景解释了一遍——**可实际上，你一个字都没解释。**

模型一年比一年强。可大多数人的用法还停在原地：每次对话从一张白纸开始，把 Claude 当临时工，用完就扔。Skills 就是在这个地方动手的——Claude 从此是一个**已经接受过充分培训的专职助理**。

**类比：**就像餐厅的 SOP 手册。新厨师来了不需要主厨每道菜盯着教，手册里有食材比例、火候标准、摆盘规范。人换了，味道不变。

能做成 Skill 的事几乎没有边界：内容创作（品牌语气、文章结构、写作禁忌）、研究与分析（分析框架、输出格式、信息源偏好）、语法与编辑（不喜欢的句式、错误清单、审校标准）、外联与销售（邮件模板、信息提炼、个性化策略）、求职应聘（简历、经历亮点、自我定位叙述）……

**核心原则：任何你会重复告诉 Claude 的事情，都值得变成一个 Skill。**

## 02 四步构建你的第一个 Skill

启用 → 描述 → 保存 → 调用，全程不超过半小时。

### 01 启用 Skill-Creator

Customize → Skills

进入 Claude 账户的 **Customize → Skills**，开启「Skill-Creator」。这是 Anthropic 官方预置的特殊 Skill，只干一件事：**帮你构建其他 Skills**。写高质量 Skill 文件本身有门槛——怎么组织信息、写规则、给示例、设自查清单，这些知识它已内置。

**类比：**用 Skill 造 Skill，像用机床造机床。第一台是别人给的，后面所有台自己产。

### 02 把你的需求告诉 Claude

启用后直接说：「我想为**【某项工作流】**构建一个 Skill，帮我构建它。」

想建得更好，用结构化提示词把上下文一次给全：

```
你正在构建一个 Claude Skill——以 Markdown 格式保存的可复用指令集。

我的 Skill 用于：[描述任务]

以下是 Claude 完成此任务需要的上下文：
- 我的名字/品牌：[你的名字或公司名]
- 我的受众：[你在为谁写作]
- 我的语气和风格：[正式/亲切/简洁…]
- 我的输出标准：[好输出长什么样]
- 需要避免的内容：[禁忌词、格式要求]

请用上述上下文，编写一个完整的 SKILL.md 文件，要求：
1. 一行文字说明此 Skill 的功能
2. 定义 Skill 激活时 Claude 扮演的角色
3. 列出必须遵守的具体规则
4. 至少包含一个优质输出的真实示例
5. 以输出前自查的质量清单结尾
```

**关键细节：**上下文越具体，Skill 越好用。「语气要专业」是废话；「参考 Paul Graham：直接、不废话、句子短」才是指令。

### 03 保存到账户

Claude 构建完毕输出 Markdown 文件（有时是 zip），点「Copy to Skills」保存到账户。同时在本地建专用文件夹（如 ~/Documents/Claude-Skills/）备份所有 .md：方便日后编辑迭代，账户出问题时本地备份是唯一保障。

### 04 调用

Customize → Skills → My Skills 确认启用。之后任何对话里一句话触发：

- 用我的品牌音调 Skill，写一封【主题】的通知邮件
- 用我的语法检查 Skill 审校这段文字
- 用我的研究 Skill，整理关于【话题】的核心观点

**从此不用再解释你是谁，不用再重复标准，不用再粘背景。一句话，它全知道。**

## 03 如何构建真正好用的 Skill

核心围绕**业务场景闭环、能力可编排、边界可收敛**落地，五步：

1. 精准定位目标业务场景，梳理高频意图、实体参数与交互规则，明确能力边界，避免功能泛化。
2. 按标准化流程做能力拆解、Prompt 约束、工具函数封装与多轮对话适配，兼顾通用性与场景定制性。
3. 接入 RAG 知识库补充业务知识，配置入参出参校验、异常兜底话术与失败重试机制。
4. 做好版本管理、灰度上线、真实会话数据回流，持续优化意图识别、指令匹配和工具调用准确率。
5. 建立可复用模板库，沉淀标准化组件，实现快速复用、低成本迭代——**听得懂、调用准、能闭环、易维护**。

**7 个动作，按作用排序：**

### 01 反向提问，让 Claude 来引导你

不必自己想清楚该给什么，让它来问你：「我想构建一个 [X] Skill，请问我 10 到 50 个问题，帮助你更好地构建它。」这些问题本身就是一份清单。**答完，90% 的活已经干完了。**

### 02 反向发现，找你从没想到的场景

Skills 更狠的用法是**找出你还没意识到自己在重复的那些事**。告诉 Claude：「基于你对我的了解，哪些工作流对我来说最适合构建成 Skill？」

### 03 把现有对话直接转化成 Skill（最被低估的一招）

你和 Claude 就某个话题聊过很多次？那段记录就是最好的原料。直接说：「把我们这段对话里的一切，转化成一个 Skill 文件。」真实案例：作者的语法检查 Skill 就是这样来的——聊了几个月的偏好被完整理解，**一步到位**生成精准文件。

### 04 贴一个真实范例，胜过一百条规则（提升质量最快的单一动作）

「语气要自然」「别写套话」写十条，不如给一个样本。把那篇你觉得完美的文章**直接粘进 Skill 文件**，加一句「这是我想要的输出质量，以此为标准」。抽象描述往往是在偷懒。

### 05 把第一稿当草稿，迭代三轮才满意

读完第一版，把所有「不对劲、太笼统、少了点什么」的地方写下来让它改。费时间，不费精力——你只负责指出问题，动手的是它。

### 06 在 Skill 结尾加一个自查清单

放 3~5 个生成输出前要问自己的问题：符合语气要求吗？有没有禁忌词？格式符合标准吗？达到示例质量水平吗？相当于**把质控流程内化进 Skill 本身**。

### 07 手动通读 Skill 文件

最枯燥但「无论如何都要做」。含糊的规则、歧义的描述，试用时不一定暴露，手动阅读时显而易见。

## 04 Claude Skills 2.0 解决了什么

### 内置评估与测试：终于能知道 Skill 是否真的在工作

以前「感觉不错」就当它正常，模型微调后 Skill 可能早已失效。现在保存前可测试：写几个真实提示词，Claude 运行两次（一次激活 Skill、一次不激活），按预定义「断言」打分并并排对比。断言示例：输出不超过 200 字、必须包含数据来源、语气对话式。**从「凭感觉」到「有依据」。**

### A/B 测试：改进不再靠猜

原版和修改版对同一组提示词各跑一遍，输出并排呈现直接对比。**改版不再靠感觉，靠实验。**

### 触发词优化：解决「Skill 根本不响应」

Skill 描述不清晰或措辞与调用方式不匹配，Skill 就不会被触发。2.0 自动重写并测试不同版本描述，测量各种调用措辞下的触发成功率，找到最可靠版本。

使用方式（加载目标 Skill 的对话里）：

- 对这个 Skill 做评估
- 帮我 A/B 测试这两个版本
- 优化这个 Skill 的触发描述

## 05 七种已经验证的 Skill 类型

1. **品牌音调 Skill**：核心价值主张、受众画像、语气形容词、禁忌词清单、输出范例、不同内容类型专属规则。
2. **PDF 生成器 Skill**：布局规范（页眉页脚/字号/间距）、内容组织方式、视觉风格。
3. **文件摘要 Skill**：输出格式、必须保留的信息类型（数据/结论/行动项）、长度控制。**关键是一致性**。
4. **ELI5 Skill**：把复杂话题翻译成普通人能理解的语言。禁用术语、生活化类比、目标读者背景设定。
5. **求职 Skill**：预存简历、项目经历、核心技能、叙述方式；给职位描述即生成针对性求职信。个人效率场景 ROI 最高之一。
6. **学习 Skill**：信息呈现顺序、讲解深度、必给结构——按你最容易接受的方式呈现。
7. **健康与健身 Skill**：预存目标、限制、偏好、当前基础。

## 07 总结：它解决的不只是效率

每次打开新对话，Claude 什么都不知道——这是时间损耗；更隐性的代价是**质量不稳定**：每次解释措辞不同，理解就有偏差，输出上下浮动，今天写的和上周写的不像同一个人的手笔。

一个建好的 Skill 存着你最精准的自我描述，每次被叫醒都**原样呈现**——不会健忘，不会懈怠，不会在第 50 次对话时突然忘记你不喜欢感叹号。

**THE ONE THING：任何你会重复告诉 Claude 的事情，都值得变成一个 Skill。**从今天起，挑一件你重复说过三次以上的事，把它写下来。
