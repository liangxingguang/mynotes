## 何时使用
- anydoc 转换后的 Markdown 需要提炼成笔记摘要
- 抓取到的网页正文需要提炼成笔记摘要

## 阅读策略
1. 先读标题结构与字数，判断长度
2. 正文 ≤ 24000 字符：一次通读，直接生成摘要
3. 正文 > 24000 字符：按一级/二级标题切段，逐段阅读并提炼要点，读完再归并成一条摘要
4. 正文 > 120000 字符：只处理前若干章节，输出 summary_status = partial 并在笔记中注明

## 输出结构
{
  "title": "简洁标题（≤30 字）",
  "summary": "1-3 句话说清主题与结论（越简洁越好）",
  "key_points": ["核心要点（≤8 条）"],
  "tags": ["从 Index/tags.json 的 active 词表中选 1-2 个"],
  "category": "技术 | 生活 | 随笔 | 资讯 | 学习"
}

## 约束
- 摘要（summary + key_points 合计）**≤1000 字**，越简洁越好：宁短勿长，能一句话说清就不用三句
- 只依据原文，不臆造；表格与代码保留关键信息
- 语言与原文主体语言一致
- 不调用任何外部 API，不执行任何脚本
- 结果用于笔记的「摘要」与「核心要点」段落，须符合笔记模板
