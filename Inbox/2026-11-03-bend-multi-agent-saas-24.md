# B端系统多智能体重构SaaS业务流：产品经理建议收藏

> 多智能体不是给 SaaS 加聊天机器人，而是把"人找功能"改成"Agent 找决策"：把流程中的判断从人身上剥离，交给多个 Agent 协作执行。三层架构（交互层意图与槽位/编排层 Orchestrator 任务卡片/执行层工具 API 调用）、业务流重构五步法（拆业务事件找决策点→定义 Agent 角色与边界→设计结构化协作协议→嵌入权限审计与人工干预→离线评测集+影子模式回滚）、四个案例（ERP 采买到付款/车贷审批/OA 差旅报销/CRM 线索培育）、Agent 化 PRD 新增五模块（Agent 能力卡片/协作时序/护栏机制/评测集/指标）。

## 核心要点

- 传统 SaaS 隐含假设：流程稳定、角色明确、数据靠人搬运；真实业务里异常、判断、跨系统协作高频发生
- 堆功能三恶果：用户认知负担越重、跨系统协作依赖人工导出对账、异常场景依赖工单响应慢
- 核心转变：多智能体改变的是把流程中的判断从人身上剥离出来，交给多个 Agent 协作执行
- 判断标准：如果一个"AI 功能"只生成文本但不调用业务系统，那不叫多智能体
- 三层架构：交互层（用户意图入口：对话/表单/消息卡片/快捷键，设计"意图与槽位"不只是页面）；编排层（Orchestrator 把业务事件拆成子任务分发给执行 Agent，核心产物是任务卡片：上下文/约束/期望输出/超时策略）；执行层（Agent 调用工具/API/规则引擎完成查询计算审批写入，工具必须可版本化可审计）
- 五步法之拆业务事件：不按功能模块拆，按"业务事件"拆（ERP 采买到付款：请采买单提交→预算校验→供应商比价→采买订单→收货入库→发票校验→付款）
- Agent 角色边界：每个 Agent 要有身份、目标、工具、不能做的事（预算 Agent 只能读预算表不能改历史数据；财务 Agent 可发起付款计划但需人工确认）
- 协作协议：Agent 之间用结构化消息通信不用自然语言自由发挥；任务卡片含任务 ID、来源事件、业务上下文、可用数据范围、期望输出格式、失败回退路径
- 权限审计：每个 Agent 执行前校验身份与数据范围；关键动作强留痕；高风险节点强制人工确认；权限模型沿用 RBAC+ABAC 但必须增加"Agent 权限"维度
- 评测回滚：离线评测集+影子模式上线对比人工处理结果；异常时能回滚到人工流程
- 案例 ERP：采买 Agent 采集需求生成采买单→预算 Agent 实时校验余额不足通知补报或升级→供应商 Agent 按物料/交付周期/历史评分推荐→风控 Agent 校验黑名单与关联交易→财务 Agent 生成付款计划→人工在采买审批与付款两节点确认
- 案例车贷：进件 Agent 抽取 OCR 信息→反欺诈 Agent 校验设备指纹/关系图谱/历史欺诈标签输出风险标签→风控 Agent 按规则引擎评分输出额度建议→放款 Agent 生成指令人工复核；边界：反欺诈只输出标签不输出拒绝结论，风控不能改规则参数，放款不能跳过人工复核
- 案例 OA 差旅：行程 Agent 识别申请→合规 Agent 校验标准→预算 Agent 锁定预算→财务 Agent 生成报销单；超标自动推经济舱/标准酒店而非直接驳回
- 案例 CRM：线索 Agent 评分、内容 Agent 生成触达、SDR Agent 安排跟进；线索分配从静态规则变为按意向动态调整
- Agent 化 PRD 五新增：Agent 能力卡片（名称/目标/输入/输出/工具/权限）、协作时序（状态机/时序图）、护栏机制（不可覆盖规则/人工退出路径/灰度策略）、评测集（典型 case/边界 case/预期输出）、指标（任务完成率/人工介入率/业务周期/风险拦截率）

## 正文

### 一、为什么 B 端系统不能再堆功能？

传统 SaaS 的隐含假设是：流程稳定、角色明确、数据靠人搬运。但真实业务里，异常、判断、跨系统协作高频发生。

- 功能越多，用户认知负担越重
- 跨系统协作依赖人工导出、对账
- 异常场景依赖工单与用户支持，响应慢

多智能体改变的是：把流程中的判断从人身上剥离出来，交给多个 Agent 协作执行。

> 多智能体不是把 AI 塞进流程，而是让流程本身具备判断力。

### 二、多智能体重构 SaaS 的三层架构

1. **交互层**：用户意图入口，可以是对话、表单、消息卡片、快捷键。产品经理要设计"意图与槽位"，而不只是页面。
2. **编排层**：Orchestrator 把业务事件拆成子任务，分发给执行 Agent。核心产物是任务卡片：上下文、约束、期望输出、超时策略。
3. **执行层**：Agent 调用工具/API/规则引擎，完成查询、计算、审批、写入。工具必须可版本化、可审计。

判断标准：如果一个"AI 功能"只生成文本，但不调用业务系统，那不叫多智能体。

### 三、业务流重构五步法

**步骤 1：拆业务事件，找决策点**——不要按功能模块拆，按"业务事件"拆。例如 ERP 采买到付款：请采买单提交、预算校验、供应商比价、采买订单、收货入库、发票校验、付款。

**步骤 2：定义 Agent 角色与边界**——每个 Agent 要有身份、目标、工具、不能做的事。例如预算 Agent 只能读预算表，不能改历史数据；财务 Agent 可发起付款计划，但需要人工确认。

**步骤 3：设计协作协议**——Agent 之间用结构化消息通信，不用自然语言自由发挥。任务卡片包含：任务 ID、来源事件、业务上下文、可用数据范围、期望输出格式、失败回退路径。

**步骤 4：嵌入权限、审计与人工干预**——每个 Agent 执行前校验身份与数据范围；关键动作强留痕；高风险节点强制人工确认。权限模型可沿用 RBAC+ABAC，但必须增加"Agent 权限"维度。

**步骤 5：建立评测与回滚机制**——离线评测集+影子模式上线，对比人工处理结果；异常时能回滚到人工流程。

### 四、多行业案例拆解

**案例 1：ERP 采买到付款**

背景：某制造企业采买审批慢，预算超支靠人工事后发现。

Agent 协作流：采买 Agent 采集需求并生成采买单；预算 Agent 实时校验部门预算，余额不足时通知采买人补报或升级审批；供应商 Agent 根据物料、交付周期、历史评分推给供应商；风控 Agent 校验供应商黑名单与关联交易；财务 Agent 生成付款计划；人工在采买审批与付款两个节点确认。

PRD 要点：预算 Agent 工具为读预算表、写预算锁定；权限为不可修改历史预算；协作协议为"预算余额不足时，向采买人返回替代方案，不直接终止流程"。

**案例 2：车贷审批**

背景：进件资料多，人工审核慢，欺诈识别依赖经验。

Agent 协作流：进件 Agent 抽取 OCR 信息，归一化客户、车辆、经销店数据；反欺诈 Agent 校验设备指纹、关系图谱、历史欺诈标签，输出风险标签；风控 Agent 按规则引擎评分，输出额度建议与拒绝原因；放款 Agent 生成放款指令，人工复核后执行。

权限边界：反欺诈 Agent 只输出风险标签，不输出拒绝结论；风控 Agent 不能修改规则参数；放款 Agent 不能跳过人工复核。

**案例 3：OA 差旅报销**

行程 Agent 识别出差申请，合规 Agent 校验差旅标准，预算 Agent 锁定部门预算，财务 Agent 生成报销单。超标时自动推经济舱/标准酒店，而不是直接驳回。

**案例 4：CRM 线索培育**

线索 Agent 评分，内容 Agent 生成触达，SDR Agent 安排跟进。线索分配不再是静态规则，而是根据意向动态调整。

### 五、产品经理 PRD 模板要改什么？

传统 PRD 写页面、字段、流程。Agent 化 PRD 要增加五个模块：

- Agent 能力卡片：名称、目标、输入、输出、工具、权限
- 协作时序：用状态机/时序图描述多 Agent 交互
- 护栏机制：不可覆盖规则、人工退出路径、灰度策略
- 评测集：典型 case、边界 case、预期输出
- 指标：任务完成率、人工介入率、业务周期、风险拦截率
