> **摘要**：腾讯云数据库团队的思考：让 Coding Agent 越用越懂项目，涉及两个问题——如何表达项目知识（本体/Ontology 从知识工程角度把领域概念、关系、成立条件表达成可共享模型，区别于 Schema/知识图谱/RAG）与如何利用执行反馈让后续任务受益（RSI 递归自我改进：Reflexion 留反馈经验、Agent Workflow Memory 归纳可复用工作流、EvoOntology 让本体根据 Agent 使用反馈演进、Skill∞ 把优化过程本身变成可修改对象）。团队实践：在研发 Loop（设计完成→上线前测试由 Agent 承担）中，用四类记忆资产（Chat Memory、Wiki、CodeGraph、Skill）加**三层互索引项目图谱**——工程事实（静态、函数/字段/跨仓契约关联）、项目语义（LLM 提取的功能职责/业务概念/跨仓映射，本体体现在此层）、错误与经验 bug_fixed（历史 Bug 挂到相关节点，渐进式披露）。Bug 定位成功率从 58% 提升到 65%。核心立场：经验要有归属、能被纠正，本体与 RSI 结合需同时具备"能关联"和"能纠正"的能力。项目已开源：TencentDB Agent Memory。

## 核心要点

- **本体是什么**：把一个领域有哪些概念、概念间什么关系、有哪些成立条件，明确表达成可共享的模型（如"订单"与"发货单"是概念、"订单对应发货单"是关系，拆单规则随业务版本变化时条件要带适用范围）；区分"表达规则"与"确认数据满足规则"（SHACL/业务程序负责校验，写下规则不等于现实已遵守）。
- **与 Schema/知识图谱/RAG 的区别**：Schema 管数据组织、图谱管实体关联、RAG 管检索供给，本体强调对象与关系的共同含义；检索到一份材料后还需判断它在说哪个对象、在什么条件下成立、能支持哪步推断；图谱所有边都叫"相关"并不解决问题，连接更多节点≠表达更准确的关系。
- **Palantir 与 FDE 的启示**：Palantir Ontology 把 data/logic/action/security 结合，业务对象与操作和权限连接；FDE（Forward Deployed Engineer）深入业务现场，需把用户目标、既有系统、交付标准连起来——Agent 越接近实际操作，这类含义澄清越难省略。
- **Memory 与 RSI**：任务反复执行≠系统已学会，跨任务学习需单独设计；Reflexion 说明反馈可成为记忆，Agent Workflow Memory 说明记忆也可以是"怎样做"；保存≠学会、复用≠改进，错误经验被更稳定召回会让错误重复得更稳定；RSI 递归性体现在三层——执行内迭代（改当前任务产物）、跨任务自改进（改持久知识/工具/方法）、改进过程的自改进（改生成/选择/验证改进的方法，如 Darwin Gödel Machine、Skill∞ 的 meta-skill）。
- **EvoOntology 思路**：本体拆 Content/Schema/Tool 三部分，提供 browse（找语义相关对象）/resolve（取对象及关联记录）两类访问；演进时先分析执行轨迹，判断限制来自内容缺失、工具暴露还是 Schema 无法表达，再做局部候选修改、与原版本同条件下对比，达标才保留；测试集冻结，不能边看答案边补语义。
- **团队实践：研发 Loop + 三层图谱**：Agent 承担设计完成到上线前测试（实现、验证、定位修复），人定目标与业务取舍；四类记忆资产 + 三层互索引图谱——①工程事实（静态，函数/类型/字段/接口及跨仓契约关联，跨仓边须经 API/消息/Schema 契约核对，不能仅凭同名符号连边）；②项目语义（结合工程分析与 LLM 提取职责、概念、字段含义、跨仓映射与约束，LLM 候选关系不能仅凭语言流畅升级为项目事实）；③bug_fixed 错误与经验（历史 Bug 整理成经验挂到前两层节点，区分"一次事件"与"可复用经验"，故障表现/根因/补丁位置可能不同）。本体不必成为第四层，体现在第二层概念约束与跨层角色区分中。
- **三层互索引的用法**：模型可从任意层进入（有符号从工程层、纯业务需求先找概念、遇故障先查经验），不固定执行顺序；渐进式披露——先给关联理由/风险摘要/适用范围，再展开触发条件与检查方法，最后读完整证据；关键前提（版本、权限、项目范围）必须随摘要出现，图遍历要有预算和停止条件。
- **经验要可纠正**：概念卡应含易混淆对象、状态作用域、工程映射、关键约束、验证入口；经验至少保留现象、触发条件、原因依据、处理方式、不适用条件；旧结论被替代后引用它的摘要/Skill/测试假设应进入待复核，原事件不删但不能继续以已确认规则指导新任务；"读过但没落实"提醒仅靠召回日志不能确定经验生效，经验使用应能追踪到它改变了哪项判断/实现/验证。
- **初步结果与检验**：内部 Bug 定位试验成功率 58%→65%（+7pp），尚不能换算为完整研发效率提升；后续需分层对照（工程图/语义/经验各自贡献）、同材料同预算比较（排除信息增多因素）、区分"已知故障找回旧解"与"未见问题用他域经验迁移"两种价值；持续学习实验用冻结图谱组与只吸收已结束任务经验组对照，并保留旧任务回归；学习过程不能自行放宽业务目标与权限（不能删失败用例提成绩），成本需计入端到端等待时间。
