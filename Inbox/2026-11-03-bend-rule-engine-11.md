# 规则引擎：B端产品经理如何把复杂业务规则做成可配置决策中台？

> 本文用三个真实场景讲透规则引擎设计：车贷审批、CRM客户分层、物流运费计算。核心组成（事实/条件/动作/规则集/决策表/优先级/互斥组/默认规则/版本）、通用产品设计框架（六模块）、规则引擎与机器学习的配合方式，以及面试高频题。

## 核心要点

- 规则引擎核心：接收事实→匹配规则→执行动作；不是"把 if-else 搬进数据库"，而是结构化表达管理复杂决策
- 九大核心组成：事实、条件、动作、规则集、决策表、优先级、互斥组、默认规则、版本
- 车贷审批案例：6 条规则（R001-R006），优先级数字越大越先执行，命中即结束；互斥组避免冲突；默认规则 R006 保底
- CRM客户分层案例：RFM 模型（近期消费/频次/金额），标签实时计算不依赖数仓定时任务，运营可视化配置
- 物流运费案例：规则可嵌套（计费重量→基础运费→附加费），前一条输出作为后一条事实，需定义规则链
- 通用框架六模块：规则目录、规则配置、规则测试、规则发布（草稿→测试→灰度→全量→回滚）、规则监控、规则权限
- 规则引擎 vs 机器学习：规则引擎处理确定性/合规/强解释场景，机器学习处理概率预警/异常识别/推荐；组合使用（模型输出风险分，规则引擎按分执行动作）

## 正文

### 核心概念

规则引擎将业务决策从代码中分离，接收事实（Fact）→匹配规则（Rule）→执行动作（Action）。PM 要理解：业务人员能看懂规则、规则之间能排优先级、规则变更能灰度发布、执行过程能回溯。

### 案例一：车贷审批规则引擎

事实：申请人信息、车辆信息、贷款申请信息、第三方征信数据。规则集：基础准入、反欺诈、信用评分、额度、人工复核。

决策表示例：
- R001 年龄<18 或 >65 → 拒绝，优先级 100，互斥组"基础准入"
- R002 征信评分<550 → 拒绝，优先级 90
- R003 收入负债比>70% → 拒绝/降额，优先级 80
- R004 贷款金额>车辆价格×0.8 → 降额至车辆价格×0.8，优先级 70
- R005 高风险地区 → 人工复核，优先级 60
- R006 其他情况 → 通过，优先级 0，默认规则

关键设计点：优先级数字越大越先执行，命中 R001 直接结束不继续匹配；互斥组内只执行优先级较高一条避免冲突；默认规则 R006 确保所有事实都有结果；版本管理每次调整生成新版本灰度发布；执行日志记录命中规则、条件求值过程、结果动作。

### 案例二：CRM客户分层规则引擎

事实：近期消费时间（R）、频次（F）、金额（M）、活跃行为、会员等级。规则集：价值分层、流失预警、高价值保护。

决策表示例：
- C001 近30天消费>5000 且频次>3 → 打标签 S 级，触发专属支持，优先级 100
- C002 近90天无消费 且历史金额>10000 → 高价值流失预警，触发召回优惠，优先级 90
- C003 近180天无消费 → 沉默客户，触达频率降低，优先级 80
- C004 其他 → 普通客户，优先级 0

设计要点：标签由规则引擎输出实时计算不依赖数仓定时任务；配置界面可视化运营人员下拉框选择无需写代码；历史数据沙箱上线前验证分层结果；监控分层人数占比异常时告警。

### 案例三：物流运费计算规则引擎

事实：包裹重量、体积、发件地、目的地、承运商、时效要求、是否偏远。规则集：基础运费、附加费、承运商选择、时效承诺。

决策表示例：
- L001 体积重>实际重量×1.2 → 计费重量=体积重，优先级 100
- L002 偏远地区 → 附加费=偏远费，优先级 90
- L003 当日达 → 选择承运商A运费上浮20%，优先级 80
- L004 其他 → 默认承运商，优先级 0

设计要点：规则可嵌套（先算计费重量再算基础运费再叠加附加费）；前一条输出作为后一条事实需定义规则链；版本管理承运商价格调整只改参数不改结构；灰度发布新价格先对部分商家生效。

### 通用产品设计框架

1. **规则目录**：按业务域分组（审批/营销/计费）
2. **规则配置**：条件编辑器、动作编辑器、决策表、DSL
3. **规则测试**：沙箱环境、历史数据回放、预期结果比对
4. **规则发布**：草稿→测试→灰度→全量→回滚
5. **规则监控**：异常率、执行耗时、规则冲突告警
6. **规则权限**：业务人员可编辑参数，规则结构由产品/技术维护

### 规则引擎 vs 机器学习

规则引擎适合确定性、合规性、强解释性场景（反欺诈兜底、准入规则）；机器学习适合概率预警、异常识别、推荐排序。组合：机器学习输出风险分，规则引擎按分执行动作。如风控模型输出欺骗概率，规则引擎设定概率>0.9拒绝、0.5-0.9人工复核、<0.5通过。
