# 用一棵树管住 100+ 个红点：SLG 红点系统实现详解

> 游戏开发系列·红点系统：在"前缀树+父节点脏集合"主流方案基础上把"计算"也合并——拉模式叶子自订阅自计算、脏标记冒泡到根、每帧后序遍历只算脏节点，新增红点只需一个类+一行注册。

## 核心要点

- **方案定位**：用三问给方案分类（怎么汇总/何时计算/谁来算）。主流方案 D（前缀树+父脏集合）只合并了"汇总"，本文把"计算"也合并：叶子只标脏、每帧统一算，业务从"推值"变"只说变了"。
- **拉模式**：叶子自己订阅数据事件、收到只标脏；计算写在 `GetCount()`（当前数据的纯函数）里由框架调用。一个红点全部逻辑收在一个类，业务代码零改动，事件风暴无害（标脏幂等近零成本）。
- **脏标记冒泡 + 每帧合批**：`SetDirty()` 沿父链标脏到根（O(深度)≈常数）；每帧后序遍历，叶子脏则算、中间节点只求和——不管来多少事件，每节点每帧最多算一次。代价是最多延迟一帧。
- **关键细节**：脏标记必须**先取走再计算**，否则遍历中新标脏会被父节点误清、红点停在旧值；变更通知走事件队列而非同步回调，防 UI 在遍历中途改树。
- **有意全树遍历**：干净节点遍历仅微秒级，省的是"计算"而非遍历；全树 Update 顺带让时间驱动红点（冷却/跨天）在叶子 OnUpdate 自查标脏，无需外部定时器。
- **工程配套**：建树与 Init 分开（防登录数据未齐时红点闪烁）；UI 组件"先拉后推"、显示压制只动 UI 层不碰数值；路径常量+注册表建树、重名/叶子挂子节点建树期报错；Inspector 下拉选路径+GM 调试。
