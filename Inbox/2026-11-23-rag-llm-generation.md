# RAG 中的大模型生成：最后一公里

> RAG 系列第四篇，讲检索之后的"最后一公里"：检索→上下文构建→生成→输出。涵盖 Prompt 工程（角色/限定信息源/格式/兜底四原则、温度值调参）、上下文构建（筛选、去重、窗口管理、结构化）、长文本 Small2Big、多文档问答引用增强、表格问答、上下文压缩与答案溯源，目标是让模型严格锚定证据、抑制幻觉、可溯源。

## 核心要点

- **生成定位**：LLM 是"智能整合器+语言表达器"，与纯问答的区别在于严格锚定检索资料而非依赖自身记忆；缓解幻觉三管齐下——Prompt 工程、上下文构建（重排/去重/结构化/窗口管理）、溯源与校验。
- **Prompt 工程四原则**：明确角色、限定信息源（仅基于资料回答）、规定输出格式、兜底策略（无证据返回"无法回答"）；进阶要素含动态模板路由与温度调参（事实型 0.0–0.3、解释型 0.4–0.7、创意型 0.8–1.0）。
- **Lost in Middle**：多资料输入时模型易忽略中间信息，对策为按相关度/逻辑重排资料、分段输入、提示词要求全面覆盖。
- **上下文构建**：核心任务是在有限空间内放最有用的内容；流程为多路召回→阈值/重排/相关性判别过滤→RRF 精排→去重合并→TOKEN 预算管理→结构化组织；原则是"少即是多、上下文=模型的世界、结构决定理解力、可追溯"。
- **长文本问答**：增大 chunk_size/TopK/后置 rerank 均有局限；正解是动态分片（chunk≈256+层级解析+编号）+ Small2Big 补全——"精准命中靠向量，相对完整靠邻居"，以原始块为中心扩展邻居并去重。
- **多文档问答**：多源检索融合（BM25+向量+RRF）→ 用 `<document X>` 标签包裹并编号的结构化上下文 → 引用增强生成（显式引用或内联引用 `[1]@ref`）；可先分文档摘要再全局整合，支持引用链追踪与冲突提示。
- **表格问答**：表格解析→结构化文本/摘要→可读文本；模型对比结论为 DeepSeek-32B 综合最强、Qwen2.5-32B 稳定、TableGPT2-7B 偏弱。
- **上下文压缩与答案溯源**：压缩可减 30%–80% token，但非必需——先试不压缩能否解决，避免信息丢失；溯源用分离式架构（先生成答案再独立溯源），两阶段策略：n-gram 文本匹配召回（阈值）→ LLM Rerank 精选最相关出处。
