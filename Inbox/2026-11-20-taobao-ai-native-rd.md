> **摘要**：淘海外技术团队的 AI Native 研发范式升级实践。第一阶段 SDD 驱动：自然语言写清设计规格，规格即指令、代码是规格的产物，六阶段 SOP（项目准备→需求澄清→技术提案→提案执行→测试执行→完结归档），AI Coding 占比从 5% 提至 85%，但业务体感不明显——编码时间只占需求全周期约 20%，编码 200% 提效只带来约 10% 真实提效，瓶颈在"需求→PRD→实现→验收"的串行流转。第二阶段 Agent 驱动：以钉群为统一工作界面，"AI 执行 + 人决策"，一句话触发、四类 AI 分身自动接力走完澄清→方案→编码→数据全链路，真人只守三个卡点（PRD 人工确认、AI 测试验收、真人终验）。按需求复杂度分两种流程：≤5 人日小需求群内闭环当天上线，>5 人日大需求群内做驾驶舱、编码回归 IDE。已在供给/支付/营销三域验证，小需求研发估时降低 50%。

## 核心要点

- **SDD 阶段成果与体感误差**：文档驱动前后端代码生成（规格即指令、代码是规格产物），六阶段 SOP 流程化卡点+分阶段评审；AI Coding 占比 5%→85%，但业务仍感觉在排期——编码时间只占需求全周期约 20%，编码 200% 提效仅带来约 10% 真实提效，大量时间花在需求对焦、PRD 编写评审、方案评审、联调测试。瓶颈隐藏在"需求→PRD→实现→验收"串行流转中，杠杆点在协同模式转变：串行协同 → 并行协同，人写人审 → AI 生成人决策。
- **范式底层判断**：拉齐业产技工作界面、降低沟通协同时间；ChatBox 是迄今大规模跨人群验证的 AI 产品范式（钉钉是最大的 ChatBox 场景）；给钉钉装 Agent 大脑，可端到端完成协作与执行。未来排期性质变化：从"研发资源排队"变为"风险与依赖排队"，所有角色一起为业务价值负责。
- **核心方案**：把"人驱动"交付链路重构为"AI 执行 + 人决策"——运营在钉群一句话发起业务方向，产品/技术PM/研发/分析师四类 AI 分身自动接力走完需求澄清、方案设计、编码交付、数据分析；真人只在三个卡点把关（PRD 人工确认、AI 测试验收、真人终验）；数据回流形成可迭代闭环；协作总线、产出留痕、交叉评审、高风险动作强制卡点做工程保障。
- **关键路径三要素**：通道——钉群作为唯一工作界面和上下文载体，文档/邮件/会议直接在群沉淀；角色——AI 负责产出（起草、检索、汇总、编码），人负责决策（澄清、取舍、放行、灰度）；流程——需求→设计→澄清评审 GATE→交付→发布上线 GATE 整链在项目群执行。
- **目标指标**：结果——小需求（≤5 人日）零研发投入、Agent 端到端当天上线；中大型需求交付周期压缩 20%~30%；月度交付量提升 40%；质量底线（千行 bug、故障率、回滚率不劣于基线）。过程——范式渗透率、AI 初稿采纳率 ≥80%+（定稿由 AI 初稿迭代而非推翻重写）、澄清评审效率、AI Coding 占比（小需求 90%→99%~100%，中大型 60%→90%）。
- **按复杂度的双流程**：≤5 人日——编码、测试、验收全部群内完成，AI 直接生成 Diff 与 Test Report，追求一次性成功率；>5 人日——群内聚焦 MRD/PRD/技术方案评审与上下游协同，vibe coding 回本地 IDE 完成后回群更新。统一原则：需求推进、产出物、关键决策都留在群内，卡片消息流转即时留痕。
- **自动化交付验证**：PRD 与技术方案合并为机器可执行 Spec，AI 自动跑编码、单测、回归、部署、校验、发布，人只守方案放行、核心 CR、灰度放行三个 GATE；流水线挂客观质量门禁（单测、Lint、安全、回归、线上指标），异常自动回滚；人工卡点按风险分级 L1 轻量闭环到 L4 完全人工决策。
- **实践成果**：供给、支付、营销三域完成真实项目验证；供给域小需求实现 MRD→PRD→方案→编码→部署→测试→发布群内交付，AI 通过代码分析纠正技术方案使研发估时降低 50%；巴拿马等复杂需求形成"群内协同、IDE 研发"组合模式；支付/供给域打通会议听记→行动项→技术方案→CR→交付；营销域生成 PRD 初稿与交互 Demo。
- **进一步迭代**：运营群内发起→AI 分身接力→真人仅终验的自迭代闭环；数据回流校准知识库；面向管理者的可观测、可管控、可纠偏后台；从"AI 分身"（需求级，一需求一群，需求结束群解散）走向"数字员工"（常驻业务域、职责范围与授权边界内主动认领需求，超出边界才升级给人）。
- **总结**：AI 参与度分 L1~L3 级，小需求已达 L3，大部分需求仍停留 L2；下一步四件事——流程规约（SDD 规约+AAIC Skill 托管调度，把回 IDE 的部分逐步演进为自动执行）、文档质量（提示词与知识库让 AI 初稿可直接评审定稿）、工程底座（Skill 编排、机器人响应、确认人身份校验与跨组织授权）、资产迭代（埋点度量+数字资产回流）。跑通后衡量口径从"AI 生码率"转向"端到端交付周期"，交付吞吐取决于知识库质量、领域 Skill 覆盖度与权限边界管控的可信度。
