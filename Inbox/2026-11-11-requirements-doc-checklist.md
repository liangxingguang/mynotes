# 一页完整需求分析文档结构检查清单

> 把需求分析各环节（目标与场景、模块拆分、范围界定、用户故事、功能清单、验收标准）收束成一份九段式检查清单：写文档时搭结构、写完后自检、评审时当对照表。

## 核心要点

1. **九段结构**：背景与目标 → 用户与关键场景 → 范围界定（必须做/后做/不做）→ 功能模块与用户故事 → 功能清单 → 验收标准 → 非功能与约束（建议有）→ 优先级与排期（建议有）→ 基线与变更
2. **用户故事标准句式**：作为【角色】，我想要【行动】，以便【价值】；故事严格对应"本期必须做"，不夹带后做/不做内容
3. **功能清单必要字段**：编号、功能名称、对应故事/模块、关键规则摘要、依赖、范围、验收要点
4. **验收标准句式**："在【前提】下，当【操作】时，系统应【可观察结果】"，覆盖正常路径+主要异常，禁用"流畅""良好"等主观词
5. **一致性铁律**：范围、故事、清单、验收标准四处信息必须一致，避免多套说法
6. **使用提醒**：先保证"必须有"项完整再补建议项；中小项目不必面面俱到；清单是检查工具不是写作模板的全部；一页纸价值在于可执行
