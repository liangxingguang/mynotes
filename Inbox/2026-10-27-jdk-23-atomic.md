# AtomicInteger / AtomicLong / AtomicBoolean —— 无锁并发的基石

> Atomic 三兄弟通过 volatile 保证可见性、CAS 保证原子性，用无锁自旋替代 synchronized，是理解整个 JUC 的前置知识。文章剖析其 Unsafe + CAS 源码（底层落到 CPU 的 lock cmpxchg 指令），讲解 ABA 问题、伪共享、高并发空转等痛点，并给出计数器、一次性初始化标记、ID 生成器等典型用法与选型建议。

## 核心要点

- 核心公式：AtomicInteger = volatile（可见性）+ CAS 自旋（原子性），无锁无线程挂起
- CAS 底层是 CPU 的 cmpxchg 指令加 lock 前缀锁缓存行，硬件级原子
- AtomicBoolean 内部用 volatile int（1=true/0=false）存储，因为 Unsafe 没有 boolean 版 CAS
- 高并发下同变量 CAS 空转严重，万级争抢应改用 LongAdder 分段累加
- ABA 问题（值改了一圈又回来）需用 AtomicStampedReference 带版本号解决；计数器场景不受影响
- 读多写极少用 volatile 就够；"先 get 再判断再操作"非原子，须用 CAS 自旋或 updateAndGet
