# 驾驭 Coding Agent：打造 AI 原生研发工作流

> 摘要：继上篇"生产代码边际成本趋近于零、生产好软件成本依然高昂"之后，本文拆解如何用工程化思维驾驭 Coding Agent、告别提示词玄学。主线：架构决策必须在 AI 写码之前完成；真正的杠杆是规约工程 + 上下文工程而非措辞；落地为"AI 研发任务五要素模型"；从 Assistant 到 Agent 让开发者实际扮演技术负责人；最后用测试、Review 与可观测性守住最后一公里。

## 核心要点

- **架构先行**：架构的本质不是背大厂最佳实践，而是在充满限制的现实里做残酷权衡。AI 能一秒列出含 Kafka/Redis 集群/Netty 网关的豪华微服务方案，但 3 人后端团队的理性选择是模块化单体；内部低频后台不需要分布式缓存；核心账务清算在关键链路绝不能为吞吐指标妥协。团队人力、硬件预算、上线窗口、历史包袱只有你清楚。
- **从提示词工程走向规约 + 上下文工程**：研究"怎么说话"只解决皮毛。**规约**精确定义"应该做什么"与"绝对不能做什么"；**上下文**至少含 5 项：框架约定与目录规范、领域模型与数据字典（Schema）、接口契约与安全规则（鉴权/脱敏/多租户）、全局异常与编码惯例、既有架构决策（为何某处看似冗余却不能删）。落地：项目根目录维护高质量 `CLAUDE.md` / `AGENTS.md` / `.cursorrules`，把红线、风格、工具约定固化为**项目级静态上下文**。
- **五要素模型**：每次派活集齐 Goal（目标）、Scope（范围与禁区）、Context（参考文件/表结构/范例）、Constraints（硬性红线、性能要求、兼容规则）、Done（可执行验收标准）。按这五维组织语言时，你不是在和聊天机器人对话，而是在**编写一份结构严谨的工程任务书**，据称能把翻车概率降低 80%。
- **Assistant → Agent 的分水岭**：前者解决"单点动作"，你仍是踩油门的司机；后者解决"端到端目标"——自己扫仓库、检索模块、制定多步计划、跨文件写入、沙箱跑测试、读报错自我修正，最后交出干净 Git Diff 与测试绿灯报告。
- **你正在变成工程指挥官**，需三项过去属于技术负责人的能力：① **任务拆解与编排**——需求太大直接丢给 Agent 会上下文爆炸，必须拆成正交、可控、可独立验证的子任务 ② **锁定变更边界**——永远别让 Agent 一次性在后台静默改几十个文件，**先对齐方案再动手**，小步快跑逐个模块验证 ③ **及时熔断与重置**——连续两次原地打转、"修一个 Bug 引出三个新报错"时果断回滚、清空被污染的上下文，回头查自己的规约和边界。
- **验证是生死护城河**：AI 的危险在于**用最自信的语气、最规范的命名、最优雅的排版，写出含致命逻辑漏洞的代码**——手工时代不确定的代码显得犹豫生涩、容易在 Review 中被警觉，AI 时代错误代码和正确代码看起来一样漂亮。三件事：① 测试先行 + 极端边界审视（AI 擅长主流程，极易漏并发重入、事务回滚、空指针、外部调用超时、权限越界）② **不仅看"它写了什么"，更要看"它漏了什么"**（大事务夹耗时 RPC、分页无最大条数、敏感数据漏脱敏、破坏缓存与库一致性）③ 可观测性兜底（日志埋点、业务指标、告警阈值仍需亲自把关）。
- **工程铁律**：AI 可以替你生成代码，但永远不会替你在凌晨三点的线上故障复盘会上背锅。**对软件结果承担最终责任的，永远是按下 Merge 按钮的那个人类工程师。** AI 时代的软件工程非但没有变成"随便说句话就生成 App"的儿戏，反而对工程规范性提出了更高要求。


## 正文

> 采集说明：原文约 6.4 千字符，已一次通读。抓取时**配图全部未加载**（残留 1px SVG 占位符）；第 03 节"五要素模型"的示例代码块被截断，只剩一行「【Goal 目标】」，五要素的完整写法请看原文；其余文字完整。

**01 架构先行**：在让 AI 写任何一行实现代码之前，先完成架构决策。开篇那个"死循环"很真实——一开始觉得 AI 是神，几十秒吐几百行；真正在项目里一跑编译，要么引用的底层方法根本不存在，要么破坏了原有权限拦截逻辑，改好一个小 Bug 顺手改崩三个老接口；最后花在擦屁股和排查幻觉上的时间比自己手写还长。解法是把提问方式从"这个功能怎么用代码实现？"换成"**在当前的真实约束下，这个系统应该长什么样？为什么？**"

**02 规约工程与上下文工程**：过去两年大家都在研究提示词工程——怎么措辞、怎么设定角色、怎么加魔法咒语。但对严肃的软件工程而言，这只解决了皮毛。AI 写出的代码常像"格格不入的外来户"，因为它看不到你脑子里的隐性工程背景；有效的上下文绝不止当前打开的那个文件。

**03 给 AI 派活的五要素模型**：项目级静态规范打底之后，每次具体派活还要注入"任务级动态规约"。文章用"密码重置"功能举例，按 Goal/Scope/Context/Constraints/Done 五段式下达指令。核心认知是：现代软件开发的范式转移在于**不再把 AI 当作靠运气抽卡的黑盒，而是当作一个需要明确边界、提供充足上下文、并严格验收的工程参与者**。

**04 从 Assistant 到 Agent**：哪怕职级只是刚工作一两年的年轻程序员，面对 Coding Agent 时你实际上已经在扮演过去技术负责人的角色——任务拆解与编排、锁定变更边界、及时熔断与重置。

**05 守住最后一公里**：验证、测试与系统可观测性不再是可有可无的收尾工作，而是决定生死的护城河。代码生成速度越快，未经严格验证的代码流入生产环境的风险就呈指数级上升。

**06 写在最后**：下一篇预告"当表面功夫被彻底抹平，我们该如何进化为真正的 AI 原生软件工程师"——谈初级岗位的剧变、晋升阶梯的重构、以及该把时间投资在哪些不可替代的底层能力上。
