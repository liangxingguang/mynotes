> **摘要**：星舰是用户使用的协作平台，Cloud Agent 是其内部负责云端执行的后台服务——为 Agent 安排远程沙箱、启动并管理执行、收集结果交回星舰展示。本文以"读取项目生成报告"任务为例拆解架构：星舰接收要求→Cloud Agent 安排执行→沙箱中 Agent 读项目写报告→Cloud Agent 收集报告→星舰展示。任务生命周期六阶段（登记→找环境→备料→启动 Agent→收回报告→交回结论），强调执行结果与交付完整性分开表达。会话管理区分会话/轮次/执行环境三层，中断恢复分四种情况与三种粒度，更换引擎用适配层统一五类交互。

## 核心要点

- **角色边界**：星舰（接收要求、组织工作流、展示结果，不直接承载构建/测试/文件操作）；Cloud Agent（记录任务、安排环境、启动管理执行、收集结果，不替代 Agent 理解项目）；沙箱（提供工具/目录/算力，不理解报告结论）；Agent（读项目、调工具、形成结论写文件，不管理平台排队/资源/归档）。
- **为何独立沙箱**：Agent 的读取文件/装依赖/跑构建测试与在线业务服务负载不同，混在业务容器会挤占资源、发布重启中断任务；独立沙箱将实际工作移出业务服务，星舰复用已有沙箱能力而非重建算力平台。
- **任务六阶段**：登记任务（含仓库版本/材料/Agent/工具/时长等执行条件，先存记录再安排执行避免重启后失联）→申请环境（复用需核对身份/授权/用途，不能因环境仍在就默认继承权限）→备料（取仓库/放附件/备工具，环境准备与 Agent 工作分开记录）→启动 Agent 持续接收过程→收回报告（识别本次生成修改的文件，非所有工作文件都交付）→交回结论与文件。
- **执行结果≠交付完整性**：正常结束不等于文件全部交付、也不等于业务验收通过；执行失败但初稿已归档应同时表达"执行失败"+"初稿可下载"；正常结束但附件未收回不能只给笼统成功。"完成"分引擎结束/归档处理/文件完整/业务验收多层。
- **三个关键机制**（设计要求）：创建请求去重（同一次创建及其重试用同一稳定标识，文字相同不等于同一次创建）；取消/超时阻止后续执行（受理取消≠实际生效，停止后自动拉起/续跑须先查原任务是否允许）；执行结束但收集失败时列出缺失项及影响，已归档部分仍可交付。
- **会话管理**：会话（跨多轮的持续工作关系）/轮次（会话中一条消息及处理）/执行环境（沙箱目录工具进程，可保留或回收，与会话记录分离）三层；会话记录不只是聊天，还须保存文件；进程退出/环境保留/沙箱回收是三个不同动作。
- **中断恢复四情况**（设计要求）：用户关页面（仅展示连接断开，非任务取消）；管理服务重启（新节点先查任务记录再核对现场，管理权接管需回答归属失效/唯一确认/旧节点恢复后哪些操作失效）；Agent 进程退出（按保留材料判断是否续原环境，权限额度问题先修正条件）；沙箱终止（只能靠已存历史/归档/快照重备环境）。区分"连不上"与"已终止"，恢复分接管进程/恢复文件续会话/重新执行三种粒度。
- **引擎适配层**：统一启动/过程输出/正常结束/异常结束/会话恢复五类交互，参数形式不同在适配层转换，引擎只给部分信息时不补造缺失记录；适配层解决"不同 Agent 怎么接入"，不是让所有 Agent 表现一致。
