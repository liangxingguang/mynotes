# 【JVM 底层修炼记】从 JDK 8 到 JDK 21：ZGC 与低延迟垃圾回收器的演进

> ZGC 低停顿的两大核心机制（染色指针 + 读屏障）、从 JDK 11 实验到 JDK 21 分代 ZGC 的版本演进，以及 JDK 8→21 的 GC 选型建议，是《JVM 底层修炼记》系列的收官篇。

## 核心要点

1. **传统 GC 的瓶颈**：Parallel GC 以 STW 为主，CMS/G1 虽有并发但初始标记、最终标记、对象转移等阶段仍需停顿；并发回收依赖写/读屏障等协调机制带来额外开销。ZGC 的设计思路是把标记、对象转移等耗时工作尽量转移到业务线程运行期间并发完成，必须 STW 的工作压缩到极短阶段，目标为亚毫秒级停顿、停顿不随堆容量与存活集简单增长、支持多 TB 堆。
2. **染色指针**：ZGC 直接利用 64 位对象引用的部分比特位携带 GC 元数据（标记状态、是否需要重新映射、终结处理状态等），免去每次访问对象头判断的成本，并为并发对象转移后修复旧引用提供基础；位布局随版本演进，并非永久不变。
3. **读屏障（自愈机制）**：对象并发转移后业务线程仍持旧引用，读屏障在加载堆对象引用时检查指针状态，按需查转发表修正旧引用、写回并返回新引用，使业务线程不必等待转移完成即可访问对象；读屏障有运行时开销，ZGC 并非零 STW。
4. **分代 ZGC（JDK 21）**：引入前 ZGC 不分代，短命对象与长命对象同体系管理，导致回收工作量大、CPU 开销高、分配停顿风险。JDK 21 按弱分代假说划分年轻代/老年代，写屏障记录跨代引用，可降 CPU 开销与堆开销、改善高分配速率场景效率；JDK 23 分代成默认模式，JDK 24 移除非分代模式。
5. **版本事实**：JDK 8 已有 G1（`-XX:+UseG1GC`，默认仍是 Parallel GC）；JDK 17 的 ZGC 生产可用但非分代；JDK 21 需 `-XX:+UseZGC -XX:+ZGenerational` 显式开启分代模式。
6. **选型建议**：优先考虑 ZGC 的场景是接口延迟极敏感（风控、高频交易、P99/P999 严格的微服务）与大内存、高分配速率（TB 级堆、缓存/大规模对象处理）；小堆且 G1 已满足的业务不必强切。ZGC 是并发回收器，须为并发预留堆空间，重点监控分配速率、Live Set、堆余量、GC CPU、分配停顿与尾延迟，用 `-Xlog:gc*` 观察，最终以压测对比 G1 与 ZGC 决定。
7. **系列收官**：从原理、工具、问题分析到性能优化构成完整 JVM 知识体系，学习目的在于面对真实生产问题时能理解 JVM 行为、定位瓶颈、有效解决。
