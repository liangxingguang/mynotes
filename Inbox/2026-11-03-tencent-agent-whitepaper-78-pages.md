# 78 页讲透 Agent 落地：腾讯企业智能体路线图

> 摘要：腾讯 2026 全球数字生态大会发布 78 页《AI Agent 企业解决方案及落地实践》。核心观点：企业智能体三阶段跃迁（能对话→能干活→能上岗），分界线不是模型强弱而是责任边界；产品骨架四层（WorkBuddy/ClawPro/Agent Runtime/TokenHub）可当立项拆解线；白皮书篇幅最重的是内部提效而非对外创新；Agent 第一波价值在对内省钱，第二波才是卖产品；落地门槛不在模型，在流程有没有被写清楚。

## 核心要点

1. 三阶段跃迁：知识问答（对提问负责）→ 办公助手/Agent 工作台（对动作负责）→ 数字员工（对结果负责，按 KPI 交付）；分界线是责任边界而非模型强弱
2. 第三代办公范式：人给目标、设边界、做判断；数字员工理解上下文、持续执行、交付结果
3. 四块底座：WorkBuddy（企业级智能体，执行主体）、ClawPro（Agent 管控台，管权限/边界/审计）、Agent Runtime（执行引擎/云沙箱/记忆/网关/可观测）、TokenHub（多模型统一调度路由）
4. 四层可当立项拆解线：谁干活、谁管、跑在哪、用哪个模型；模型层（TokenHub）最易被高估，权限与审计（ClawPro）应先理清
5. 九章目录中篇幅最厚的是内部提效（研发运维全链路），信号：Agent 第一波价值在对内省，第二波才对外售
6. 被重点展开的业务方向符合同一形状：人天密集、动作重复、结果可验收（内容生产、智能客服、研发运维）；动作模糊、结果难验收的谈得少
7. 高管时间表：具身智能 80 分模型 2 年内、通用机器人 5~8 年；出海营销 90%+ 任务可由 Agent 实现；素材产能一人一天从 10 条到上千条
8. 关键判断：人的精力成卡点——模型能逐帧描述广告内容却说不出哪几秒最关键，预算决策还得人拍板；技术瓶颈正让位给判断瓶颈
9. 工程企业三动作：从岗位立项（算重复动作吃掉的人天）不从平台立项；把 SOP 写成可调用的 Skill；先内部跑通再对外交付
10. 一句话总结：Agent 的门槛不在模型，在流程有没有被写清楚；企业先得把流程讲得明白到机器能听懂

## 正文

**背景**：10 月 29-30 日，2026 腾讯全球数字生态大会互联网与数字技术专场发布 78 页《AI Agent 企业解决方案及落地实践》。它不像产品说明书，更像一张时间表：什么阶段该上、从哪一层上、哪条业务线先跑通。本文为易海工程AI的行业观察解读。

**一、三阶段跃迁：从能对话，到能干活，再到能上岗**
- 第一段知识问答（DeepSeek、ChatGPT 类）：本质是问答工具，只对你的提问负责
- 第二段办公助手：Agent 工作台 + 业务系统集成，嵌进工作流、调用工具、操作文档，对动作负责
- 第三段数字员工：进入系统、操作数据、完成业务闭环并对结果负责；人负责给目标、设边界、做判断，数字员工理解上下文、持续执行、交付结果

对企业最有用的价值：把"我们公司 AI 用得怎么样"变成可自查的问题。多数工程企业今天停在第一段（买几个问答工具，写方案时查规范、改措辞）；真正省人天的是第二、三段，因为它们接的是流程，不是聊天框。

**二、四块底座：手册的产品骨架，正好是一条立项拆解线**
- WorkBuddy · 企业级智能体：第三代办公范式的执行主体，给目标和边界，调工具、操作文档、持续执行，交付一项完成的工作而非一份文件
- ClawPro · Agent 管控台：管权限、管边界、管审计；企业真正卡住的地方往往不是模型不够聪明，而是不敢把核心系统交给说不清权限的助手
- Agent Runtime · 基础设施：执行引擎、云沙箱、记忆、网关、可观测五件套；长任务断续、跑错回溯靠这一层
- TokenHub · 模型服务入口：混元/第三方/开源模型统一调度、按场景路由；不必把身家押在一个模型上，换模型不该等于重做系统

工程企业用处：做预算、写立项报告时照这四层拆，不会出现"上一个 AI 到底买的是哪部分"的糊涂账。提醒：第四层（模型）最易被高估——模型换来换去，往往不如把第二层的权限和审计先理清。

**三、九章目录：篇幅最重的不是对外的创新，是对内的提效**
九章覆盖：AI 整体方案、内部提效、技术底座、SaaS Agent、内容生产、AI 社交陪伴、游戏内 AI 玩法、运营与智能客服、WorkBuddy 生态共建。两个信号：
1. 全书篇幅最厚的是内部提效（研发运维全链路），而非对外卖钱的业务创新——Agent 第一波价值在对内省，第二波才是做成产品卖给客户
2. 被重点展开的业务方向几乎都符合同一形状：人天密集、动作重复、结果可验收（内容生产、智能客服、研发运维）；动作模糊、结果难验收的谈得少

**四、三条判断，和一个 5 到 8 年的时间表**
发布会后媒体群访，腾讯云互联网行业技术总经理陈亮与钛动科技"钛极"大模型负责人丁俊玮各给一张进度表：
- 具身智能：80 分模型 2 年内，通用机器人 5 到 8 年
- 出海营销：90% 以上任务可被 Agent 实现（洞察、创意生产、投放调优）
- 素材产能：一人一天从 10 条到上千条

陈亮：AI 在游戏行业降本增效"落地和验证最多"，但业态级创新还在试点（游戏生产过程太复杂）。丁俊玮：广告营销九成以上任务可交给 Agent。

真正值得记下的一句：人的精力成了卡点——模型能逐帧描述一条广告的内容，却说不出哪几秒最关键；真金白银的预算决策还得人来拍板。技术瓶颈正在让位给判断瓶颈，这条规律移植到工程行业同样成立。

**对工程企业的三个动作**：
1. 从岗位立项，不从平台立项：挑一个具体岗位的重复动作（投标资料整理、图纸会审纪要、进度周报汇总、材料询价比价），先算它一周吃掉多少人天，再谈要不要上系统
2. 把 SOP 写成能被调用的 Skill：手册反复讲 Skill——把部门标准作业程序沉淀成 Agent 可直接调用的能力库；工程企业的 SOP（工序、验收、标书模板）是最全的，是被严重低估的资产
3. 先内部跑通，再对外交付：内部提效不用给客户看，容错高、验收快，是最适合做第一个 PoC 的地方；内部跑顺后再谈把 Agent 嵌进交付物

**结语**：78 页翻完，能带走的一句话是——Agent 的门槛不在模型，在流程有没有被写清楚。三阶段跃迁的前提，是企业先把自己的流程讲得明白到机器能听懂。工程行业最不缺流程，缺的是把流程翻译成机器能执行的那一步。这一步没人能替你做，包括出这本手册的人。
