# 打造高性能、低 CPU 消耗系统——36 种编码实战技巧（上篇）

> 基于百万 QPS 高并发系统经验的 Java 编码手册，上篇讲前 18 个技巧（共 36 个、100+ 案例）。主线思想是"CPU 漏斗"：砍掉一切多余的类型转换、对象创建、字符串操作与无效分支，让 CPU 只做核心运算——核心手段是全链路统一原生类型、相同数据只取一次、快速失败、用 O(1) 查找替代 O(n) 判断、用原生类型集合降低 GC。作者强调仅适用于有性能痛点的高并发场景，否则应优先可读性与可维护性。

## 核心要点

1. **统一类型、简化类型**：全链路（传输/存储/计算/缓存）类型一致，ID 用 Long、状态用 int/枚举；禁止循环内 String↔Long 转换与包装类自动拆装箱，序列化只做一次；能数字不用字符串、能基本类型不用包装类、能单变量不用集合，数字状态必须配枚举注释防魔法值。
2. **字符串是 CPU 重灾区**：String 不可变，`+` 拼接每次产生新对象——用 StringBuilder、日志占位符，杜绝循环内拼接；少用 split/正则/截取，改用下标匹配、定长截取或结构化协议。
3. **相同数据只取一次**：同一请求/方法内禁止重复查库、重复 RPC、重复计算、重复解析，用局部变量、请求缓存、批量查询复用结果。
4. **快速失败 + 原生循环**：复杂校验拆成有序独立的前置判断，非法请求尽早 return；遍历优先数组/ArrayList（连续内存、缓存命中、零 GC，比链表快 10~100 倍）；高并发核心链路用普通 for，不用 forEach/Lambda/Stream（额外函数式接口与迭代器对象）。
5. **日期与异常**：格式化器全局 static final 复用、统一时区、循环内只取一次时间；存储/比较/过期判断优先 long 时间戳毫秒加减（性能最强），禁用 SimpleDateFormat 与 Calendar；异常生成要抓完整调用栈属重量级操作，靠事前校验在源头消灭异常，禁止循环内 try-catch 与异常兜底业务逻辑。
6. **O(1) 替代分支**：白名单/多值匹配用 `Set.contains` 替代链式 equals；多层 if-else/策略路由在初始化时构建 Map（key=条件，value=处理逻辑），运行时一次哈希定位。
7. **对象与 GC**：GC 问题先查代码而不是调 JVM 参数——循环内对象外提、避免自动装箱、固定集合设为 static final；字段设为 null 不省内存（对象存在则引用槽位全额占用，64 位压缩指针下每字段 4 字节），整个对象为 null 才真正不占堆；只需 key 时遍历用 keySet() 不用 entrySet()。
8. **更高效的数据结构与传输**：JDK 集合包装类有对象头（16 字节开销）与装箱成本，高频数字集合用 fastutil（TIntArrayList/TIntObjectHashMap 等，内存 1/2~1/4、速度 3~10 倍）；微服务间少用 JSON 字符串传参（文本协议、反复序列化），内部优先二进制实体对象传输。

## 正文

文章定位为可常备对照的性能编码"百科全书"，每个技巧按"核心原理 → 实现方式 → 注意事项 → 落地经验（正反案例）"展开，反复强调的机理是：类型转换本质是内存解析与字节重组、字符串与异常/日期格式化会制造大量临时对象触发 GC、顺序分支是 O(n) 而哈希寻址是 O(1)、数组连续内存享受 CPU 缓存预加载。

上篇 18 个技巧一览：

1. **减少数据类型转换**：数字↔字符串↔字节↔对象↔枚举之间不频繁互转；RPC 接口明确类型，老系统兼容只在外层做一层适配。
2. **越简单的类型越好**：优先 int/long/boolean 等栈上原生类型；状态用数字+枚举，核心链路禁复杂类型，跨服务传简单 DTO。
3. **减少字符串拼接**：StringBuilder、日志占位符 `{}`，业务上减少无意义组装。
4. **减少相同数据多次调用**：局部变量/请求缓存/本地缓存/批量查询，消除重复 IO、网络与序列化。
5. **多次判断拆分、快速失败**：校验前置、有序、独立，非法输入尽早终止，避免无效封装/RPC/查询。
6. **优先数组遍历**（原文标题误植为"快速失败"）：数组与 ArrayList 连续内存、O(1) 随机访问、无迭代器开销、零 GC，避免 LinkedList。
7. **能用 for 就别用 forEach/Lambda/Stream**：原生 for 零对象；Lambda 生成函数式接口实例、Consumer、迭代器，高并发下增加 GC。
8. **减少字符串分割**：split 涉及字符遍历、正则匹配与数组拆分；用下标匹配、固定截取、预拆分或结构替代文本。
9. **优化日期解析**：`System.currentTimeMillis()`/`new Date()` 是内核态调用；DateTimeFormatter 全局 static final、时区统一 Asia/Shanghai；时间加减三档：时间戳数值运算（高并发首选）> JDK8 LocalDateTime（可读性好）> Calendar（禁用）。
10. **减少异常开销**：异常创建需生成完整栈轨迹，成本远高于普通判断；事前校验、正常流程走主干，避免两三行逻辑被几十行防御代码包裹。
11. **避免重复代码**：公共判断/计算/赋值/异常处理/RPC 校验抽成公共方法，重复代码无法被 JIT 深度优化。
12. **Set.contains 替代链式 equals**：HashSet 哈希寻址 O(1)，替代 `equals("A")||equals("B")...` 的 O(n) 硬编码。
13. **多层 if-else 转 O(1) Map 查找**：初始化期构建条件→处理逻辑/结果的 Map，运行时零分支，也更易维护。
14. **避免不必要的对象创建**（原文标题误植）：GC 频繁先改代码而非调 JVM（作者称 JDK 25 GC 已很强）；对象外提、循环内全程基本类型、固定字典 static final、拼接常量复用。
15. **使用更高效的数据结构**：fastutil 提供无装箱的原生类型集合，TIntArrayList 代 List\<Integer\>、TIntObjectHashMap 代 HashMap\<Integer,?\> 等，省内存且更快。
16. **减少 null 字段**：`new User()` 后字段全 null 仍占对象头+全部引用槽+对齐填充（示例对象 28 字节一分不少）；只有整体引用为 null 才只占 4 字节指针、堆中无实例。
17. **循环 Map 优先 keySet**：只需 key 时 entrySet() 每轮创建 Entry/Node 包装对象。
18. **减少 JSON 字符串传参**：JSON 是文本协议、序列化开销大、跨语言强但性能一般；内部服务间用二进制实体传输更紧凑高效。
