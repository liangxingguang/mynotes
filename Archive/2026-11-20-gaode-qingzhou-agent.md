> **摘要**：轻舟 Agent 把 FDE（前沿部署工程师）模式从"部署工程师"转为"部署工程能力"，将版本/分支/代码/构建/实验/真机验证/发布整条研发链路部署到每个需求现场，产品和设计同学不必逐个平台操作即可拿到可验证、可评审、可发布的交付。一条需求归并为四个主节点：发起任务、Agent Teams 执行、按验证矩阵真机验证、发布上线；压缩的是"人必须跨平台操作"的部分而非工程节点，需求确认/代码评审/测试验收/灰度发布门禁仍保留。核心机制：多实例 Agent Teams（各职能为独立 Claude Code 实例，邮件式通信）、Aone Sandbox 沙盒、AuthX 双令牌无感鉴权与凭证隔离。以 108 模块跨业务样式升级为完整案例。

## 核心要点

- **定位**：FDE 模式有效但昂贵、难覆盖并发需求；轻舟部署的不是工程师而是工程能力，把整条研发链路部署到需求现场。压缩的是"人必须亲自跨平台操作"的部分，不是工程节点本身；传统流程 8 节点、跨 12+ 平台工具，编码变快后耗时转向送进生产流程做联调验证发布。
- **适用范围与门禁**：适用目标明确/变更边界可描述的需求（模块级样式交互、单页/单链路体验、配置逻辑排查）；不建议目标值未定义/跨团队架构调整/涉资金权限合规核心链路；保留门禁——需求确认（产品与业务负责人）、代码评审（仓库 owner）、测试验收（QA 产品走查）、灰度发布审批（按现有流程）。
- **四主节点**：发起任务→Agent Teams 执行→按验证矩阵真机验证→发布上线；Agent 建工程环境、完成版本/分支/代码/服务/配置/实验/构建、推产物到云真机、按验证矩阵进目标页面执行真机验证、发现问题定位修正、经人工确认与既有审批推进灰度发布。复杂度没消失，被 Agent 接住。
- **权限互通**：代码权限由受控公共账号按 Group 集中承接（产品不必先申请 3-4 个 Group 十几到二十多个仓库），其他平台经 NCS 鉴权无感串联；边界是只推开发分支不推主干、合入前须研发 review、可触发构建但发布须人确认、提交与登录人绑定可查、任务提交构建验证对话留平台可回看。凭证隔离是凭证层保护，不等于操作天然安全。
- **Agent Teams 多实例架构**：任务拆为主会话/前端/后端/产品经理等职能角色，每角色是独立 Claude Code 实例（Claude Opus 5.5 驱动，可切 Codex），实例间以"邮件"方式通信；选多实例而非主 Agent+subagent，因技能按需装配（各实例只整合本领域 Skill/知识）、生命周期与上下文更稳定。靠职责切分避开多 Agent 改同一文件（前端只改前端、后端只改服务端），任务结束 7 天自动回收。
- **Aone Sandbox**：编码/构建/命令执行全跑在基于 runD 安全容器的内核级隔离沙盒，保护宿主与执行资源；环境独立可定制、热备资源池降等待；但 Agent 通过已授权接口对配置/实验/发布的影响仍由授权审批约束，不因跑在沙盒而免疫。
- **AuthX 双令牌无感鉴权**：Agent 代表工作负载身份与用户身份两层，AIT（你是谁，绑定两者）+APT（持有私钥证明、防重放）；关键在凭证隔离——长期凭证（私钥/Refresh Token）永不进 Agent 运行环境，由沙盒外 Egress Sidecar 完成签名注入，沙盒内代码出问题也拿不到用户长期凭证。
- **真机验证**：模拟器/桌面无法还原真实设备字体/分辨率/容器/权限弹窗/厂商定制，故建可认领可并发真实设备池（在用 127 台、采购中 120+，截至 2026-10-28），覆盖苹果/华为/小米/vivo/OPPO 等 Android/iOS/HarmonyOS 机型，每台预置高德测试账号保证登录态/城市/历史/业务数据可重复准备。三种验证方式：Agent 自主验证、过程实时可见、手机扫码人工复核。
- **DOM 参数级核对**：多模态理解整体视觉语义，DOM 把视觉差异落到可比较参数（位置/尺寸/字号/行高/圆角/间距/颜色/容器嵌套/计算样式），经选择器/组件树/diff 映射到源码位置，逻辑像素（px/dp/pt）对齐并说明与物理像素换算；参数一致≠视觉完全一致，最终结论以真机截图对照与人工复核为准。验证矩阵按变更风险声明（影响面/系统能力依赖/机型差异/验收场景），非每个需求都验三端。
- **完整案例：108 模块样式升级**：108 个跨业务模块各自独立交付，现有四批 E2E 过程材料覆盖 96 个模块（基础推荐 16、行业推荐 43、交易广告营销 19、商家 18），每模块独立 result.json 与截图，108 模块已全部上线。result.json 从视觉差异下钻到工程原因（如相似货架横版卡片：模块标题 30px→28px、卡片标题 Medium→Bold，落到具体选择器与节点）。
- **搜索链路 UI 焕新**：覆盖搜索首页/列表/详情页，Agent 对照设计稿写代码还原自上真机验证、人做最后验收提修改意见；详情页在 iPhone 真机验证，差异下钻到返回按钮/头图区/焦点卡/模块衔接/底部功能 Bar。热点承接页无设计稿，产品说清意图 Agent 先实现再依真机效果调整，验收靠截图对照与 DOM 参数对齐而非"看起来像就过"。
- **边界与责任**：门槛下移不等于责任下移，业务确认/验收判断/发布责任仍由人承担；非"人人可用全部自动化"结论，是仍在补齐中的交付方式。
